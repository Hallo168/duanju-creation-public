# 字幕对齐规范（剪映 ASR 字幕 ↔ 台词稿）

> 适用环节：剪映拼接成片、"识别字幕"自动生成之后、套字幕模板/发布之前。2026-07-12 由 04 集实测跑通（297 条字幕全量对齐一次成功）。
> 工具：`工具/字幕提取.py`＋`工具/字幕回写.py`（直改草稿 `draft_content.json`）。机械 IO 归脚本，**逐条对词的判断归 agent 人工做**——与宪法 14"不用脚本控制剧本"不冲突：脚本只搬运文本，不做任何对错判定。

## 检查清单（质检接口·一行一规则，详解按节号查正文；改规则须清单与正文同步改）

- **C1** 对齐基准=实际进片的台词最新版：二创稿为底，被 /xiufu 或分镜阶段改过台词的单元以分镜提示词.md 修复后版本为准 → §一
- **C2** 字幕跟实际语音走：录音漏说/跳过的句子**不强行插入稿件全文**，只修实际说出部分的错字与标点——字幕必须与耳朵听到的对得上 → §一
- **C3** 用户发出“对齐字幕”即视为已关闭目标草稿，执行者**不再检测剪映进程、窗口或草稿是否打开，不重复询问确认**；回写脚本自动备份 `draft_content.json.pre_subtitle_fix.bak`（重复运行覆盖旧备份，要留多版先改名）；写完由用户在剪映重开草稿抽查首/中/尾各几条 → §二
- **C4** ASR 高频错型四类逐项过：同音人名、同音别字、全程无标点、跨句错切；**人名用错字变体全局搜一遍兜底**（一处人名错型往往全片重复出现） → §三
- **C5** 文本本体在 `materials.texts[].content`（嵌套 JSON 字符串）：改 `text` 必须同步改 `styles[].range=[0,新文本长度]`，`base_content` 同改；`recognize_text` 是识别原始记录，保留不动 → §四
- **C6** 段序按全部 text 轨合并后 `target_timerange.start` 升序对位；只动 `type=="subtitle"` 的素材（压屏字幕/标题/贴纸不碰）——提取与回写必须用同一排序，序号是唯一对位键 → §四
- **C7** JSON 读写一律 UTF-8、`ensure_ascii=False`；回写前先校验修正条数=草稿字幕条数（对不上不写盘），写完重新 `json.load` 验证合法（宪法 12 编码坑同源） → §四
- **C8** 动手前先看文件头：`draft_content.json` 首字节不是 `{` = 已被剪映加密重存，脚本会检测报错——**请用户手动解密回明文再跑**（解密归用户，agent 不自行破解）；对齐尽量在明文窗口一次做完 → §四

## 一、对齐原则

**基准的选取（C1）**：字幕校对的"正确答案"是演员（AI 配音）实际念的台词，其底稿链条是：二创稿 → /fenjing 套符号 → /xiufu 修复改词。所以：

- 默认拿二创稿正文逐段对；
- 该单元有修复记录（v2/v3…）且改动涉及台词的，以分镜提示词.md 的最新版为准；
- 两边都对不上时，以实际音频为准（见 C2）。

**字幕跟语音走（C2）**：04 集实测发现 3 处录音跳过了稿件里的个别句子（如"车卖了你怎么接活？！""急什么。"等，在时间轴上没有对应片段、时长也装不下）。判定方法：该句在字幕时间轴上无对应片段、或相邻片段时长明显容不下该句字数。处理：**不补插稿件全文**，只把实际说出的部分修正措辞和标点。理由：字幕和语音对不上比字幕少一句更伤观感（静音刷剧的观众两头都看，出声刷剧的观众会立刻发现字幕多字）。

**标点要补全**：ASR 输出几乎无标点。逐条按台词稿补回问号/感叹号/破折号/引号——字幕的情绪节奏靠标点传达（与情绪三层外化的"标点节奏"层同源）。

## 二、操作流程

1. **提取**：`python 工具/字幕提取.py "<草稿目录>" <导出txt>`——得到「序号\t开始μs\t时长μs\t文本」清单
2. **对词**：agent 逐条对照台词基准（C1），产出修正 txt（每行「序号\t修正文本」；没错的行原样保留，序号必须全量连续——回写脚本按条数校验）
3. **关草稿（用户前置负责）**：用户发出“对齐字幕”即视为已关闭目标草稿；执行者不检测剪映进程、窗口或草稿打开状态，也不重复询问确认（2026-07-21 用户裁定）
4. **回写**：`python 工具/字幕回写.py "<草稿目录>" <修正txt>`——自动备份、覆写、回读验证
5. **人工抽查**：剪映重开草稿，抽首/中/尾各几条核对样式未坏、文本正确

## 三、ASR 错型档案（04 集实录）

| 错型 | 04 集实例 | 排查手法 |
|---|---|---|
| 同音人名 | 晓禾→"小何"、静仪→"静怡"、程远舟→"程远洲/远周/陈远忠" | 每个角色名列出同音变体，全局搜（一种错型全片重复） |
| 同音别字 | 瘫子→"摊子"、厂子→"肠子/场"、潮气→"晌气"、樟脑丸→"掏挠丸"、跑得→"跑的"、比布贵→"笔不贵"、眼拙→"眼脏"、捎给您→"烧给您"、见客→"剑客" | 逐条对台词稿，重点盯名词和方言词 |
| 无标点 | 全部 297 条 | 按台词稿逐条补 |
| 跨句错切 | "戏 / 要真，先瞒 / 屋里人"被切进三条相邻字幕 | 不动时间轴，把文本按实际切点重新分配到相邻字幕卡（每卡文本与该卡语音对上即可，句子跨卡不算错） |

数字写法：ASR 出阿拉伯数字（"80万/9块9"），台词稿是汉字（"八十万/九块九"）——统一改回台词稿写法，与 {} 内文字逐字一致（见 字幕模板说明.md）。

## 四、draft_content.json 结构备忘

- 草稿位置：`H:\JianyingPro Drafts\{草稿名}\draft_content.json`（单文件 1MB+ 属正常）
- 时间单位：**微秒**（μs）
- 字幕素材：`materials.texts[]`，`type=="subtitle"`；其中：
  - `content`：**嵌套 JSON 字符串**，`{"styles":[{...,"range":[0,N]}],"text":"…"}`——改 `text` 必须把每个 `styles[].range` 终点同步为新文本长度，否则样式渲染范围错位
  - `base_content`：结构同 `content`，同步改
  - `recognize_text`：ASR 原始识别结果，**保留不动**（留作识别底账）
  - `words`：逐字时间戳（start_time/end_time/text）——不改文本级对齐可不动，剪映会按 content 渲染
- 字幕排序：`tracks[]` 里 `type=="text"` 轨道的 `segments[]`，按 `target_timerange.start` 升序=播放顺序；`material_id` 关联素材
- 写盘：UTF-8、`ensure_ascii=False`、紧凑分隔符（剪映原格式即无缩进）
- **加密坑（C8，04 集实录）**：剪映 10.7 在对齐改盘完成、用户重开草稿验收并触发保存后，把 `draft_content.json` **加密重存**（文件头变 base64 乱码、体积变大，同目录 `crypto_key_store.dat` 即密钥库）——此前一直是明文。含义：①明文窗口不保证一直在，对齐尽量一次做完；②两个脚本开头都做了首字节检测，非 `{` 直接报错退出，不会误伤加密文件；③遇到加密草稿：**报告用户、由用户手动解密回明文**（2026-07-12 用户裁定，用户有解密手段），解密后照常跑脚本——agent 不自行尝试破解密文
