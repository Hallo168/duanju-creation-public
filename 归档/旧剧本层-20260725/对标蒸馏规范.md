# 对标蒸馏规范（爆款对标剧本 → 对标卡 + 升格条目的操作规程）

> 定位：/duibiao 命令必读；/erchuang 借卡时按需查 §六。个案资产唯一存放处 = `对标库/`（对标卡），通则唯一去处 = `knowledge/爆点知识库.md`（B 条目，经用户拍板升格）。本文规定怎么把一条爆款台词稿解剖成可复用的结构资产——**蒸馏与创作分离**：本环节只解剖不改写。
> 建立：2026-07-23（用户裁定新增对标蒸馏环节：素材只收文字台词稿；复用做全三层；独立 /duibiao 命令）。

## 检查清单（质检接口·一行一规则，详解按节号查正文）

- **D1** 内核结构句必须是一句话情绪机器（触发→积累→引爆→落点四环齐全），不含人名/地名/行业/产品等专名 → §四
- **D2** 秒级节拍表逐拍带秒数区间＋功能标签，格式对齐爆点知识库§三"秒级结构模板"，各拍秒数连续且总和=来源时长 → §三
- **D3** 钩子类型/情绪杠杆优先用爆点知识库§三既有词表命名；词表没有的标"⚠️新钩型候选"，不许生造同义词；题材列用「主类/细分」双层命名、主类只许取 §二词表 → §二、§四
- **D4** 金句清单每条三件套：原句（证据引用）＋句式骨架（挖空模板）＋功能标注；每条尾注"措辞属故事层禁复用" → §三
- **D5** 台词肌理指标五项齐全：总字数／时长／字每秒密度／最长单句字数／口语肌理特征（重复、语气词、拉扯回合数）→ §三
- **D6** 「为什么爆」逐条标证据档位【数据证据／文本证据／纯推断】，纯推断条数不得过半；无数据来源时不得编造数据 → §四
- **D7** 可迁移技法逐条预写成 B 条目草稿（规则＋案例＋**机理**＋来源对标卡号），标 `类型=个体|组合`（组合须写清"A 的价值取决于 B"的相互依赖机理），带「验证记录」行（出生权重1·暂记），逐条给迁移边界（什么题材/条件下失效）→ §五
- **D8** /duibiao 现场对 knowledge/ 只记账不改规则：技法命中既有 B 条目/储备条目/他卡候补 → 就地给对方「验证记录」**暂记 +1**（注"对标NN"，机理复核过才坐实）；新技法只落本卡候补。升格/降级/淘汰一律集间按权重结算（知识库整理规范§八），报告制、用户持否决权 → §五
- **D15** 机理复核（加权前置闸）：每条技法的「机理」须过三测——①因果链非复述结果 ②说得出失效边界 ③离开原故事专名仍讲得通；任一不过则权重锁零留备选。**由质检员核**（写机理者不自证）；「为什么爆」标【纯推断】的条目一律不计权 → §五
- **D9** 对标卡内禁止二创动作：不改写台词、不出大纲、不换壳、不接产品——发现自己在"顺手改良"即停 → §一
- **D10** 新卡写盘同一次操作必须在 `对标库/INDEX.md` 追加索引行（编号/题材/集型/钩型/一句话内核/可当原稿），frontmatter `可当原稿` 与索引一致 → §六
- **D11** 复用红线：借卡只许搬结构层（节拍/机制/句式骨架），原句措辞进二创稿即违规（宪法规则1"≥8字连续相同"对对标卡原文同样生效）→ §六
- **D12** 「借卡摘要」必须是 frontmatter 后第一个 H2、≤10 行、五要素齐全（内核/框架件一行式/节拍骨架/金句功能位/慎借），且与全文一致——摘要是 /erchuang 的读取接口，摘要错=借卡全错 → §三
- **D13** 入库前先 Grep INDEX 同主类＋同钩型查重：内核近似的**合并强化进老卡**（追加「变体记录」），不另立新卡 → §七
- **D14** INDEX「一句话内核」≤40 字、单元格内不换行——索引全表必须永远轻到可安全全读 → §六

## 一、定位：两层资产，三个复用口

**为什么要这个环节**：/erchuang 第4①步每集都做"抽内核结构句"，但用完即弃——原稿换壳完，骨架就丢了，同一爆款没法喂第二集。爆点知识库§九（金句四技法，对标"拆迁款拆散老两口"篇）证明对标提炼有效，但那是手工特例。本规范把它变成流程：**每条爆款蒸一次，多集反复用**。

**两层资产**：
- **个案层 = 对标卡**（`对标库/NN-名称/对标卡.md`）：这一条爆款的完整结构解剖，随用随查
- **通则层 = B 条目**：跨题材成立的技法，经用户拍板升格进爆点知识库，此后所有集自动受益

**三个复用口**（详见 §六）：①升格条目被 /erchuang 自动读取；②/erchuang 出大纲时借对标卡框架件；③信息齐全的对标卡直接当原稿开新集。

**边界（D9）**：蒸馏是解剖学，不是编剧。对标卡里不出现"建议改成""如果是我会"式内容——那是 /erchuang 的事。

## 二、输入与判型

- **只收文字台词稿**（2026-07-23 用户裁定）：用户粘贴文本或给文件路径。视频/链接请用户先自行取得字幕文本再来
- 判型复用爆点知识库§五 A–E 表（纯台词/带说话人/带场景/完整剧本/残稿）。**但补全策略不同**：/duibiao 只为解剖服务，缺说话人/场景按最小必要推断并在卡内【推断声明】集中列出，**不做剧情补全**——残稿（E型）缺结局就标"结局缺失，节拍表止于第N拍"，不许替爆款编结局（编出来的结局会污染"为什么爆"的归因）
- 可选输入：数据表现（点赞/完播/转评/评论区热词）。有就填进 frontmatter 并成为 D6 的【数据证据】来源；没有就留空，归因只用文本证据

**分类词表（索引的地基，D3）**：题材列一律「主类/细分」双层命名。**主类是封闭词表**：`家庭｜亲情催泪｜逆袭打脸｜战神赘婿｜复仇虐渣｜甜宠｜悬疑反转｜职场｜带货`（源自爆点知识库§三匹配表＋现有卡实情）——筛卡按主类 Grep，主类各写各的=索引失效。细分自由命名 ≤6 字。词表要扩须用户拍板，扩一次全库生效；蒸馏时套不进任何主类的，标"⚠️新主类候选"待拍板，不许私自开新词。

## 四、蒸馏方法（解剖顺序，倒不得）

1. **通读定性**：题材/集型/时长，对照爆点知识库§三匹配表找最近邻题材行
2. **抽内核结构句**（D1）：只保留情绪机器。自检：把句子念给外人，听不出原故事是哪一条=合格；出现专名或具体事件=还没抽干净
3. **拆节拍表**（D2）：逐拍标秒数区间＋功能（羞辱/埋钩/阶段性胜利/泄露/引爆/收尾…优先用§三模板的功能词）。台词字数÷密度反推秒数，估算标"约"
4. **解机制**：钩子与杠杆按词表命名（D3）；信息差画清楚——观众/主角/反派各自何时知道什么，这是反转结构的本体
5. **量肌理**（D5）：五项指标照算。这是给 /erchuang "±15% 体量对齐"和"对标原稿校准"（爆点知识库四点五）当参照系的，不是装饰
6. **归因**（D6）：先写证据再下结论。有数据表现的，从数据倒推（完播高→钩子/节奏归因；评论热词→情绪命中归因）；只有文本的，归因于结构（对照§二评分卡十维度，哪几维明显拉满）。**分不清是"它好"还是"它火"的地方，如实标纯推断**
7. **筛技法并记账**（D7/D8/D15）：过"蒸馏三问"对标版——个案还是规律？（只在本题材成立=写进迁移边界，跨题材成立=候选）提炼到什么高度？（保操作性，纯态度句不合格）它为什么有效？（**写不出机理的技法不许加权**）。每条标 `类型=个体|组合`（组合须写清"A 的价值取决于 B"的相互依赖机理，否则拆成两个个体）；Grep 现役＋储备＋他卡候补记账：命中的暂记 +1、新技法落本卡候补（出生权重1·暂记）——**"暂记"待质检员机理复核过才坐实**（D15）

## 五、升格通道（权重证据制，2026-07-23 用户裁定：不再逐条请用户拍板）

核心：**对标都是爆款——技法出现是一次共现验证**，但共现≠因果（爆款有几十个因子，验证的是整套组合不是每个因子）。所以加权走**两道闸**：共现记账 + 机理复核。验证攒成权重、权重决定升降：不开评审会，用户只持否决权。加权细目、个体/组合、降级三件套、共现≠因果警告的唯一本体 = 知识库整理规范§八。

- **记账（/duibiao 蒸馏时，D8）**：技法先 Grep 爆点知识库（现役＋储备）＋对标库既有候补——命中的给对方「验证记录」**暂记 +1**（注"对标NN"，不动规则文字）；不命中的新候补写进本卡（B 草稿＋机理＋类型＋迁移边界＋验证记录行，出生权重1·暂记，D7）
- **机理复核（质检员，D15）**：/duibiao 写完卡时质检员核 D 清单，逐条查机理三测；**未过的把"暂记 +1"退回、权重锁零留备选**——这是共现制唯一的防混淆闸，写机理者不自证
- **结算（集间体检）**：机理已过、权重 ≥2 的候补 → 自动升格现役；升格致满员按权重顺位淘汰入储备（降级三件套见§八）——升降名单进集间报告，**用户不否即生效**
- **组合**：默认不升格；只有跨卡反复出现＋相互依赖机理成立，才作 `类型=组合` 登记，只奖励搭法的额外增益
- 三类升格去向：**新技法** → 爆点知识库对应节新增 B 条目；**新节拍模板**（整表质量高且题材词表没有）→ §三"秒级结构模板"新增一行；**新钩型/杠杆** → §三匹配表新增行
- **例外**：涉合规/平台风控的条目不走自动线，仍须用户事前拍板（知识库整理规范§八）

## 六、复用三个口（怎么用这些卡）

1. **通则口（自动）**：升格进爆点知识库的条目，下一次 /erchuang 读知识库时自动生效，无需任何指名
2. **借卡口（/erchuang 2.5 步）——三级加载，逐级有预算，上下文占用与库规模脱钩**：
   - **L0 索引**：只读 INDEX **活跃表**，按题材主类＋钩型筛（词表统一所以 Grep 可靠）→ 入围 **≤5 张**
   - **L1 摘要**：入围卡逐张 `Read(limit=30)` 只取 frontmatter＋「借卡摘要」——**大纲设计只用摘要**（借的本来就是框架件一句话）；出 3–4 份大纲时各份可从**不同**卡借框架件（叙事视角/时序/证据链机制/打脸触发方式/节拍结构），大纲标注「借卡：NN·借了什么」——借的是结构层，天然满足框架层置换
   - **L2 全文**：仅用户选定大纲后、需细化所借节拍/机制时才读全卡，**≤2 张**；"当原稿口"例外（指名单卡本就全读）
   - 用户选定后回写该卡「复用记录」；**同一张卡的同一组框架件连续两集使用即预警**（自家作品同质化，复用记录就是查重依据）
3. **当原稿口（无稿开新集）**：`可当原稿: true` 的卡可作 /erchuang 的替代输入——只有产品/题材没有原稿时，指名一张卡做骨架换壳。此时"台词体量对齐原稿 ±15%"的参照系 = 卡的台词肌理指标
4. **复用红线（D11）**：三个口一律只搬结构。对标卡原句（含金句原句）出现在二创稿里即违规，金句只许用句式骨架重新填肉

**INDEX.md 契约（双表制）**：**活跃表＋归档表**两张同构表——`| NN | 对标名 | 题材 | 集型 | 钩型 | 一句话内核 | 可当原稿 | 复用过的集 |`，一句话内核 ≤40 字（D14）。卡在哪张表=卡的状态（与 frontmatter `状态` 一致）；/erchuang 只读活跃表，归档表仅供翻旧账 Grep。新卡入活跃表（D10），归档=原地改 frontmatter＋行移到归档表，**不搬文件、编号引用永不断**；复用记录变更时同步"复用过的集"列。

## 七、生命周期与瘦身（价值上移、卡片退役）

核心：卡的终点不是删除，是**价值搬进爆点知识库、本体退到归档表**——升格即瘦身，库的"活跃视野"永远保持小而精。

**入库端防胖（D13）**：/duibiao 写卡前先 Grep INDEX 同主类＋同钩型——内核近似的不另立新卡，在老卡「反转与信息差机制」后追加「变体记录」小节（新素材的差异点＋新证据），INDEX 不加行。库胖的根源是重复入库。

**瘦身三动作（集间执行，随知识库整理规范§六第六检，一集进行中不做）**：
1. **聚类归档**：同主类×同钩型活跃卡 ≥3 张时，共性技法通常已因多卡验证攒到权重 ≥2 自动升格（§五）——结算后留最有代表性的 1–2 张当**样本卡**，其余转归档：通则进了知识库，个案就不用再占活跃视野
2. **榨干归档**：候补技法全部结清（已升格，或权重长期停在 1 无增长）＋连续两次借卡筛选未入围的卡 → 归档（卡归档不清账：其已升格条目的验证记录仍有效）
3. **摘要体检**：本集动过的卡抽查「借卡摘要」与全文一致性（摘要是接口，D12）

**触发阈值（兜底红线）**：单主类活跃卡 >5 或全库活跃卡 >30 → 当次集间体检**强制**过一轮瘦身，不许顺延。
