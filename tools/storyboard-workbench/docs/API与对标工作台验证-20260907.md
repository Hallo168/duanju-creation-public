## 开始使用

1. 刷新工作台，点击右上角“API 设置”。没有已启用的文字 API 时，会显示新接口表单。
2. 填写接口名称、API 地址和 Key。默认使用 Chat 兼容接口；Responses 可在“高级设置”中选择。
3. 点击“获取模型列表”，选择默认模型；供应商未提供目录时，可以手动填写完整模型名。
4. 点击“保存并用于当前会话”。Key 留空会保留已有值，主动清除需在高级设置中勾选。配置列表和任务结果不返回原始 Key。
5. 在输入框上方选择本轮接口与模型。模型从下一条消息生效，历史对话和每条回复原有的模型记录保留。

普通接口基础地址例如 `https://供应商地址/v1`。若填写完整的标准 Chat 或 Responses 生成地址，服务会识别对应末尾路径，避免重复拼接；其他特殊路径可在高级设置中填写。读取模型目录只读取目录，不发送创作规范或进行文字生成。

## 对标拆解

1. 选择“对标拆解”，拖入或选择 TXT / MD 文件。每次一份，最多 2 MB，也可在对话中直接提供文字。
2. 检查原稿预览。文件名会作为默认标题，兼容 UTF-8、带 BOM 的 UTF-16，以及常见中文 GBK / GB18030。
3. 如修改了预览，先点击“保存修改”。原始附件和每次输入版本分别保留。
4. 点击“准备拆解入库”，核对本轮模型、输入资料和写入范围后确认。
5. 后台执行现有对标命令及规范。需要其他结构卡、框架或产品资料时，通过受限的资料读取通路补齐，不编造磁盘上未读取的内容。

拆解方法、自动入库和候选确认以现有对标流程为准。文件上传本身不调用模型，也不直接把原稿写入正式对标库。只有执行拆解后，才按流程产生正式存档、卡片和索引等变更。

## 文案库与后续调用

右上角“文案库”读取当前项目已有的八类资料：对标原稿、剧情结构、带货框架、开头库、转化话术、手法库、产品资料、账号与经验。

普通原稿和数据卡可预览；包含内部规范的文件只显示文件信息，由后台继续按原流程调用。点击可复用资料的“用于选题”，会创建一个引用该资料的新选题会话，沿用当前接口和模型。其他原有会话不被覆盖。

API 成稿的“成稿并审稿”路线分成草稿和独立审稿两段，使用同一个已锁定模型。草稿先保留在后台，通过审稿后的最终结果才写入正式文件；未完成的结果留在任务记录中供核对和继续处理。

## 版本与失败处理

- 每轮启动时锁定模型、接口设置、来源版本和关键资料版本；变化后旧的确认不能继续发送。
- API 更新已有文件前须先读取当前内容。写入会检查旧版本、保留备份，并将相关文件作为一组处理。
- 新结构卡或新带货框架须连同索引一起返回；原稿存档不能丢失本轮输入的完整文字。
- 成稿和复盘对结构索引、卡片及带货框架的跨目录回写已接通，仍受原流程和目标范围限制。
- 网络中断不会自动重发同一请求。服务重启后，旧的运行中任务标记为待核实，不自动重新调用模型。
- 前台不返回原始模型通信、完整文件变更正文、内部规则应用明细和规范读取缓存。对明显的内部规范原文及认证信息回传进行拦截。

这些措施不等于已经完成公域用户登录、租户隔离和全面防套取验证。当前接口设置和文件空间仍属于本机项目的自用管理环境，不能直接视为可公开收费的多用户服务。

- 验证了 Chat 兼容与 Responses 请求使用所选模型；Responses 不复用其他模型的旧 response ID。
- 原有分镜、参考图、资产生成恢复相关回归检查通过；修复了资产任务结束状态先于最后保存释放的时序问题。
- 类型检查、针对改动的代码检查和构建通过。

联调使用的是本机模拟接口，没有用用户的真实 Key 进行付费生成。供应商的实际兼容性、生成质量和真实费用，需在工作台填入所选接口后验证；界面只显示供应商确实返回的用量，未返回的用量不按零处理。
