# 工作台分段改造方案

日期：2026-09-05<br>
性质：根据本轮沟通整理的建议稿。本次交付为方案，尚未修改工作台程序。

## 1. 改造目标

把现有清楚的任务分段做成便于操作的工作台：需要讨论时使用 Agent，输入与输出明确的步骤由程序调用模型完成，文件和生成任务的管理由代码执行。模型可以配置到部分内部步骤。

日常使用保持简单。页面按大环节组织；一个环节内部可以有多个执行步骤和不同模型。内部拆分不等于增加同样数量的页面或确认弹窗。

分镜页按用户既有要求保留。其他模块根据自己的任务设计操作区，不预设都要套用分镜的逐行表格。

## 2. 页面怎么使用

进入工作台后选择故事，再进入当前要做的环节。对标拆解、选题初期和洗稿旁路可以独立使用，不强制先绑定故事。

每个环节的主要区域显示本环节的材料与结果；上方只保留必要输入和主要操作。需要推敲时打开该环节的对话区。模型设置默认收起，页面仅显示本次使用的配置。

| 环节 | 主要操作区 | 需要讨论时 | 后台按步骤执行 |
|---|---|---|---|
| 对标拆解 | 原稿与拆解结果 | 讨论抓手、结构、疑点 | 读取指定原稿，调用分析模型，按原有规则保存卡片并更新索引 |
| 选题 | 本次条件、5 个候选、选中题的开场方案 | 推敲方向、融合候选、提出修改 | 按路线读取材料，生成候选；选定后生成开场；定案时写入选题文件 |
| 成稿 | 剧本编辑区与审稿结果 | 修改冲突、台词和具体段落 | 读取定案，生成完整剧本，单独执行原有审稿轮，保存版本 |
| 洗稿旁路 | 原稿、换皮方案、成品 | 选择和修改换皮方案 | 按选定方案执行重写与原有核验，产物仍进入独立洗稿目录 |
| 资产 | 角色、场景、道具的提示词与图片 | 调整人物外观、场景要求、处理指定图片问题 | 生成资产方案，按依赖调用生图，派生参考图，下载、核验与保存 |
| 分镜生成 | 骨架和逐单元提示词 | 讨论切分、镜头与连续性问题 | 分别执行骨架、展开和原有核对步骤，结果进入现有分镜页 |
| 视频生成与修复 | 保留现有分镜页 | 对指定单元调用 AI 修复 | 保存新版本、提交指定单元、查询、下载、技术核验 |
| 后期、封面与文案 | 所选草稿、执行进度与结果 | 修改字幕、配乐意图、封面要求 | 调用已有字幕和音轨工具；用模型处理语义修正、配乐安排和文案；按所选范围完成执行 |
| 复盘 | 数据录入与分析结果 | 讨论原因、决定哪些经验应保留 | 保存数据、计算明确指标、调用分析模型；按现有规则处理回填 |

选题仍保留“选题选择、开场选择”的自然停点。对标拆解的既定入库、资产的技术放行等自动行为继续依照原规则执行，不增加逐文件确认。

## 3. 把三种工作分清楚

### A. Agent 对话

用于需求还在变化、需要追问、需要讨论取舍或诊断的问题。对话关联当前故事、环节和具体对象，例如某个选题、某个角色或某个视频单元。

对话产生的建议与正式产物分开。下一段使用当前采用的产物及明确批注，不靠继承整段聊天记录猜测上一段的结论。

### B. 程序调用模型

用于输入和交付物已经明确的工作，例如：根据定案生成剧本、根据角色表生成资产方案、根据骨架展开分镜提示词。

程序负责准备本步应读材料、调用指定模型、接收完整结果并按现有文件契约保存。模型负责创作和语义判断。需要自查的步骤继续执行原有自查轮。

每类步骤有自己的结果字段，例如选题候选、资产条目、单元提示词；界面直接展示这些内容。避免继续把所有结果都塞进同一种“回复文本＋任意文件修改”的通用结果里。

### C. 纯代码执行

用于读取文件、复制已锁定内容、组织挂载顺序、保存版本、提交生成任务、查询状态、下载文件、媒体技术核验、字幕与音轨工具调用等确定动作。

代码只检查可明确验证的执行和文件问题。剧本是否有劲、台词是否自然、镜头是否成立，继续由模型和用户判断。

## 4. 模型配置到哪里

采用“默认配置＋必要步骤单独覆盖”。没有单独设置的步骤使用默认值。

| 可配置位置 | 配置粒度 |
|---|---|
| 日常讨论 | Agent 或支持多轮文字协作的模型接口 |
| 选题候选生成 | 可独立选择文字模型 |
| 开场方案生成 | 可沿用选题模型，也可单独设置 |
| 成稿与审稿 | 先按当前规则绑定为同一模型配置，审稿仍是单独一轮 |
| 资产方案与提示词 | 可独立选择文字模型 |
| 普通资产图片生成 | 在可用且已允许的生图接口中设置模型 |
| 分镜骨架与提示词展开 | 可以分别配置，完整执行时仍连续完成 |
| 指定内容修改或诊断 | 默认沿用当前步骤配置，可对本次执行覆盖 |
| 后期语义修正、配乐规划、发布文案 | 按需要开放独立配置 |
| 视频生成 | 延用现有分镜页的渠道与完整模型选择 |

已有固定通道和适用范围继续生效，例如当前彩铅派生的 Flow 配置。能够配置不同模型，不表示自动开放或切换全部生产通道。

界面上，每个步骤只需要一个“模型设置”入口：选择已保存的接口和模型，必要参数按模型能力显示。接口地址、密钥与协议集中配置一次，密钥由本机服务端保存，其他页面引用该配置。

接口能力要区分文字生成、图像生成、视频生成，以及是否支持工具调用。一个兼容文字聊天的 API 不自动具备执行本地脚本或操作剪映的能力。

设置在用户启动该步时确定。每次执行记录所用接口、完整模型名、提示词和输入版本；改变模型设置只影响之后启动的任务，已生成的结果保留原记录。

## 5. 用资产环节示范

这是建议优先落地的一段，执行边界清楚，也能直接验证文字模型与生图模型的分别配置。

日常使用过程：

1. 打开本集资产页，自动载入当前二创稿的角色表、场景表和产品资料。
2. 点击“生成资产方案”，程序准备本步规范并调用文字模型，展示角色、场景、道具条目及提示词。
3. 可以直接编辑条目；需要讨论时，对着该条目打开 Agent 对话。没有修改需求就继续生成。
4. 点击“生成本集资产”，按照清单一次性执行约定范围。页面显示各条目的进度和结果。
5. 程序处理明确依赖：写实人物图完成后派生相应彩铅图；全景底图完成后按既有方法派生四宫格。各步骤遵循现有生产规范。
6. 下载、格式、尺寸和完整性等技术核对通过后，自动回填清单和 `assets_ready`。用户可以事后查看并点名处理问题图。
7. 资产完成后停留在本环节。用户进入分镜阶段时，读取这份最新资产清单。

既有资产也能直接导入查看。补缺或重做只处理明确选中的范围，旧图和原任务记录保留。真实产品图仍从产品库或用户提供的文件取得。

默认沿用已有规范内的生成范围、比例和尺寸。需要使用生图接口支持的其他参数时，在对应步骤展开设置。

## 6. 分段之间如何衔接

- **正式产物继续使用现有文件。** `选题.md`、`二创稿.md`、`资产清单.md`、分镜骨架与提示词等仍是上下游依据，固定标题、目录和模式保持兼容。
- **各段能独立启动。** 已有上游文件时可以直接进入对应环节；缺材料时提示缺什么，不要求重走之前的全部过程。
- **当前段结束后停在结果。** 跨环节由用户启动；本环节已经约定连续完成的内部步骤可以继续运行。
- **内部连续性保留。** 完整分镜仍连续完成骨架和展开；完整后期仍在所选范围内连贯执行。需要时可使用单独继续或返工入口。
- **运行时锁定输入。** 每次执行记录实际读取的文件版本。用户在页面外修改了文件，后续执行读取最新版；已经生成的下游结果显示所依据的版本，输入发生变化时提示复核。
- **重做有明确范围。** 对单个角色、单个单元或指定步骤重做，不顺带重跑其他内容。
- **任务状态与产物状态分开。** 执行记录用于恢复任务；正式阶段状态仍依照现有产物和 `assets_ready`、`fenjing_ready` 推导，不另造一套互相竞争的业务状态文件。

普通规范读取、输入完整性检查和版本备份在后台执行。开始生成时，页面清楚显示本次范围及可获取的费用信息；在同一次已授权执行范围内不重复弹确认。结果未知的生成请求先核实原任务，再决定下一步。

## 7. 在现有程序上怎么改

当前已经具备可复用的基础：分镜编辑、版本保存、视频渠道目录、批量提交程序、文字 API 适配入口，以及字幕和音轨处理工具。

建议继续使用当前页面框架和本地服务，逐段迁移：

1. **整理执行层。** 从 `local-server.mjs` 中逐步分离任务步骤、接口适配、产物读写、运行记录四类职责，现有分镜接口保持可用。
2. **增加按步骤选择模型的配置。** 原来的会话级接口配置作为兼容入口；新步骤按自己的配置执行。
3. **增加具体任务入口。** 例如生成资产方案、生成本集资产、补选中资产。每个入口明确输入、执行范围和输出，不再要求用户用聊天重新描述一遍固定操作。
4. **把结果交给专用页面。** 选题显示候选，剧本显示编辑区，资产显示条目与图片；对话在需要时参与。
5. **统一上下文准备。** 规范正文继续读取 `.claude/` 和 `knowledge/` 的权威来源。代码中的步骤定义记录应读文件与结果格式，不复制一套会逐渐过期的创作规则。
6. **区分可恢复的业务数据。** 正式产物、采用的结果与版本备份保留在项目的持久存放位置；日志和临时请求可以沿用运行目录。具体存放目录在实现时与现有备份范围一起核对。

现有代码中的 API 适配入口，仅说明存在接入基础；本轮没有调用新模型、执行生图或重跑视频，实际供应商适配能力仍要在实现中验证。

## 8. 建议落地顺序与验收

### 第一批：模型配置＋完整资产环节

先把一段真正接通：载入剧本 → 生成资产方案 → 按依赖生成图片 → 下载与技术核对 → 回填资产清单。配套实现按步骤设置模型、进度显示、旧版本保留及指定范围重做。

验收重点：日常操作能直接完成任务；文字模型与生图模型确实按各自配置执行；资产清单仍可被当前分镜流程读取；现有分镜页面功能不受影响。

### 第二批：选题、成稿与文字旁路

落实候选选择、开场选择、定案、剧本编辑和原有审稿轮；对标拆解与洗稿旁路沿用自己的输入与存放位置。需要讨论时保持连续对话，已确定的操作使用明确按钮。

在保留现有分镜操作页的前提下，给分镜生成的骨架、展开步骤接入共用模型配置，仍按原有顺序和核验要求执行。

验收重点：用户选中的候选和修改能准确进入正式定案；后续生成使用当前定案；重做本段不误改其他环节。

### 第三批：后期、封面文案与复盘

复用已有字幕、时间轴和音轨工具，补齐对应任务入口、模型步骤和结果呈现。最终试听、审图和实际发布继续由用户完成。

验收重点：实际处理的草稿、分镜模式和执行范围清楚；结果能在目标应用中读取；数据计算与内容分析分开呈现。

每批先用已有产物验证导入、展示和文件兼容，再验证该批必要的执行链路。确定首批实际接口后，再按明确范围验证真实生成；不把未经实测的模型切换直接全量应用。

## 9. 方案依据

本方案依据本轮查看的实际页面、工作台源代码以及当前流程文件：

- `tools/storyboard-workbench/app/workbench.tsx`：现有分镜操作页。
- `tools/storyboard-workbench/app/pipeline/pipeline-workbench.tsx`：当前以会话为主的其他模块。
- `tools/storyboard-workbench/local-server.mjs`：阶段目录、文字接口适配、运行记录和本地程序执行。
- `CLAUDE.md`、`跨层契约.md`：权威规则和现有文件接口。
- `.claude/commands/`、`.claude/skills/`：各环节的具体流程。

上述文件保持原样。本建议把跨环节的启动交给用户，把可确定的内部执行交给程序；其他创作标准与技术放行语义按原来源沿用。
