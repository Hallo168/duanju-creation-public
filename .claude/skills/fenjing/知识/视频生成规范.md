# 视频生成规范（按统一 API 配置发现视频通道）

> 适用环节：/fenjing 产出 `分镜提示词.md` 后的逐单元视频生成。分镜产物统一置于 `分镜-15秒/` 子文件夹（含 分镜提示词.md＋成片/；2026-09-11 起废除多模式，历史 `分镜-自然段落/`、`分镜-30秒-*` 只作存量处理）；批量脚本用 `--prompt-file "分镜-15秒/分镜提示词.md"` 寻址。生成时长取各单元生成参数行。挂载=彩铅参考图＋场景四宫格图＋产品图（带货单元），全部单元无链依赖、可全并发。
> **默认通道（2026-09-09 用户裁定）＝Guagu（`providers.guagu_video`）**：生成期不再询问平台，具体模型按实时目录与本批已选完整模型核对。**TK（Symphony）已停用生成**，配置保留且 `disabled: true`，不做生成预检、参考图热预存或新任务提交；仅保留历史任务查询与下载，重新启用须由用户明确要求。**Canvas、12AI 及后续新配置项仍仅用户点名时启用**。工作台默认 Guagu，实际提交仍需用户确认。所选通道不可用、模型异常或提交结果不明时报告状态后**等用户发话**，不自动故障转移。`工具/api配置.json` 是当前可用视频通道的唯一登记处。**Guagu/Canvas/12AI 的协议细则（V7–V10）唯一出处＝`视频生成规范-备用通道.md`，使用相应通道时读取**；Dadao 的配置与执行入口已移除，V38–V40 退役且不复用编号，旧成片与账本保留。
> 各 provider 的 `base_url`、认证、端点、素材传递方式与能力以 `工具/api配置.json` 为准；新 provider 先补齐执行器与差异说明才可提交。密钥不得复制到规范正文、请求文件、任务账本或日志。
> **MJNewAPI（2026-09-10）**：用户点名时使用 `providers.mjnewapi_video` 与 `工具/mjnewapi_video_batch.py`，协议及渠道内默认模型见 `视频生成规范-备用通道.md` 的 MJNewAPI 节。统一配置及命令行执行器已接入，工作台提交尚未接入；项目整体默认仍为 Guagu。

- **V29** 子账号当日生成上限（400+`code 10001114`，没建任务没扣分）须写盘持久化标记，preflight/submit 自动跳过；次日早8点刷新失效 → §四点五E

- **V33** 执行器内置今日提交计数器：每落一条账回显 `COUNTER`；单独查用 `python 工具/symphony_video_batch.py stats`（纯本地扫账本）；数据源=全部 `symphony-*.jsonl` 按事件时间聚合（额度日=早8点起）→ §四点五C
- **V35** 平台的 generating-task-count 会大幅虚报（把已终结未清理任务算在内），不得当真相用；代理登记自提任务并逐条核实真实状态，`generating`＝核实后真实占用；多集并行共用同一池，占槽按账本溯源（POOL/THROTTLE 带归属拆解）→ §四点五C

## 一、通道选择与批次流程（2026-09-09 默认 Guagu，TK 停用，Dadao 移除）

### 1. 当前通道

| 层 | 通道 | 启用条件 |
|---|---|---|
| **默认** | **Guagu**（`providers.guagu_video`） | 默认使用，不再询问平台；模型按实时目录与本批选择核对 |
| **停用** | **TK（Symphony）**（`providers.symphony_video`，`disabled: true`） | 禁止生成预检、热预存和新提交；仅保留历史任务查询、下载，重新启用须用户明确要求 |
| **封存** | Canvas、12AI 及后续新配置项 | 仅用户明确点名时启用 |

当前启用通道的素材传递方式：Guagu 先上传为 `asset://`；Canvas 用 data URL；12AI 只接受公网 https URL——协议细则见 备用通道文件。TK 的旧协议仅保留在 §四点五。

### 2. 默认 Guagu 的批次流程（用户点名其他启用通道时按对应协议）

1. 默认 Guagu，不再询问平台；按 §一.3 核对实时目录与本批已选完整模型，读取备用通道规范 §Guagu 并运行 `工具/guagu_video_batch.py preflight`，核对挂载、台词边界、时长、画幅与费用。本地检查通过不代表远端探活成功。
2. 预检通过后按用户已授权的单元范围全量分批提交；新批次使用独立账本，重跑使用版本后缀，不做单条测试。工作台保留提交确认。
3. 费用无法可靠查询时如实记 `BUDGET unknown`，不得套用其他通道的计价；`poll` 只轮询同一批任务号，成功后下载并做技术核验。
4. 通道不可用、模型异常、参考图上传失败或提交结果不明时报告状态，按既有账本先对账；需要换通道时等用户发话，不自动重投或故障转移。

### 3. 选择与换通道流程（按用户本批选择）

1. 默认运行 `python 工具/video_provider_catalog.py --provider guagu_video` 实时查模型表；用户明确点名其他启用通道时改查相应 provider。不读上批缓存，探活失败也要标明错误；TK 停用期间不探活或启动生成代理。
2. 向用户回显：平台、**接口返回的完整模型名**、当前单价、分辨率、类型、可生产状态及素材限制。默认平台 Guagu 已获授权，不再重复询问；本批已选模型须能唯一对应实时目录，尚未选模型时再选择完整模型（"用这个"必须能从紧邻上下文唯一对应）。
3. 按"本批单元数×当前单价"给基础预算；重跑另计。历史跑通价格只作记录不作报价；本批选用的模型不得自动成为项目默认模型。启用通道的协议细则读 `视频生成规范-备用通道.md`；TK 停用期间不执行 §四点五 的新生成流程。

## 二、共同提交前预检

1. 重新读取本集 `分镜提示词.md`，确认 `fenjing_ready: true`。用户点名只跑部分单元则建白名单，只处理白名单。
2. 每单元重新读取"视频挂载""生成参数""单元提示词"，不得复用旧缓存。
3. `prompt` 的唯一合法边界是当前单元 `### 单元提示词` 后第一个 Markdown 代码块的**内部正文**：跳过开头围栏，遇闭合围栏立即停止。不得读取修复记录、任务号、失败原因、审核说明或下一单元。
4. 提交前核对 prompt 首尾：首行应为本单元素材声明，末行应为约束句；若含三反引号、`修复记录`、`失败`、`退款`、`审核`、`task_id` 等越界内容，停止并修复解析边界。
5. 检查全部挂载文件存在、非零、格式受当前平台支持；上传顺序与"图片1、图片2……"逐项一致。
6. 参数从当前单元生成参数行读取：默认 `9:16`、720p，时长按原值。模型只支持其他分辨率时，提交前报告差异由用户确认，不得静默改参数。
7. 提交脚本与通道对应：默认 Guagu `工具/guagu_video_batch.py`、MJNewAPI `工具/mjnewapi_video_batch.py`、Canvas `工具/canvas_video_batch.py`、12AI `工具/12ai_video_batch.py`；TK 执行器仅保留历史任务查询、下载，新生成已阻止。脚本行为与本规范冲突时以规范为准，先修脚本再运行。
8. **台词与提示词避开金融操作类字眼**（2026-07-25 实证）："拖款/到账/转账/打款"触发金融审核直接拒稿；改"坑了一笔/凑不齐/还不上"级生活说法。最省的位置在 /erchuang 台词层；分镜/生成层发现时须经用户授权改词并同步二创稿。
9. **被拒后禁止原样重提**（2026-07-25 实证）：平台按提示词文本去重——同文重提返回缓存拒审结果，换挂载图无效；只有文本变化才是新任务。重跑计数只对"文本有变化"的提交生效。

### A. 这个通道和别的不一样的地方

| 项 | 值 | 影响 |
|---|---|---|
| 提交入口 | 本机代理 `http://127.0.0.1:8765`，**必须先手动启动** | 代理没起＝整批连不上，不是网络问题 |
| 参考图 | **本地文件绝对路径**，最多 9 张 | 不需要图床 |
| 时长 | 只有 **5/10/12/15** 四档 | 全部单元一律15秒，正好落在档上（2026-09-11 废除自然段落模式后此缺口消失） |
| 计价 | **1秒=1积分**预付费积分池 | 每子账号积分独立（当前 2 主账号 × 15 子账号，V30）；审核失败退积分 |
| 画幅 | 竖屏 9:16，**接口没有画幅参数** | 改画幅得去平台账号设置 |
| 并发 | **单子账号同时渲染 5 条**，池上限＝子账号数×5 | 本地硬节流阀（V23）；端到端墙钟受排队时段支配，禁用固定公式估排期（V26） |
| 模型 | 短剧一律 `Dreamina Seedance 2.0` | `Video 1.5 Pro` 会把多镜头脚本揉成静止长镜头，不用 |

**两个会过期的东西**（V17 探活查的就是这两样）：
- **直连登录态**——存 Windows 凭据管理器，过期后直连全部 503 `direct_unavailable`。补救：跑一次 `node <OpenCLI入口> tiktok-symphony direct-session -f json`（入口路径见 `工具/symphony/symphony配置.json`）。
- **本机许可证**——过期后除探活外全部 403；`GET /v1/license/status` 看 `expiresAt`。

仍依赖外部项目 `外部依赖/OpenCLI-Symphony`（浏览器适配器），正常批量里只有「新参考图首次入库」会用到它。

### B. 静默无人值守运行（默认形态）

**这个通道默认全后台**：提交、轮询、下载、切账号四件事纯直连 HTTP 零浏览器。浏览器只出现在：①首次登录授权/登录态过期（一台机器一次）②**新参考图首次入库**（隐藏后台窗口，按文件 SHA-256 登记进 `工具/symphony/data/asset_cache.json`，每图一辈子一次）。

`backend` 三档：**`auto`（默认）**——缓存命中纯直连，未命中才用隐藏窗口上传；新集第一批用它。**`direct`**——绝不启动浏览器，缺登录态或缓存会明确报错；重跑批、已入库集用它，最硬的静默保证。**`browser`**——强制走 Chrome，仅直连故障时人工回退。

**新集进入全静默：先跑一次热预存 `warmup`**（把本批未入库参考图去重后一次性全部上传登记，**不扣积分**）：

```bat
python 工具/symphony_video_batch.py warmup --story-root stories/29-xxx ^
    --prompt-file 分镜-15秒/分镜提示词.md --units 1-37
```

要点：
1. 资产缓存**跨集共享、按 SHA-256 索引**（不认文件名），只有本集新生成的图需要入库；跨主账号可直接复用，warmup 在任一主账号下做一次即可（`direct_unavailable: reference image(s) are not in the direct asset cache` ＝那张图没 warmup 过，与主账号无关）。
2. 不做热预存也能跑（auto 提交时按需入库），但浏览器会被零散唤起多次并拖慢计费提交。
3. 一开始就上 `direct` 会在第一张新图上直接失败——设计如此。
4. **热预存必须经代理 `POST /v1/assets/warmup`**：绕过代理直调 OpenCLI 会把缓存写进已停用的 F 盘目录，永远命不中。
5. 入库慢的最大优化：参考图压至 1024px JPEG（200–400KB）可省约 7/8 往返。

### C. 并发、排队与子账号纪律

- **平台行为与本地授权是两件事（V23）**：平台在单账号 5 条满时仍可能接收新任务排队，但"单账号 5 条"是本地硬节流阀，执行器和代理达到上限即停止提交等空位。全量只定义任务集合，节流阀定义任一时刻允许送入平台的数量。
- **占槽真相归代理（V35）**：平台的 generating-task-count 会大幅虚报（含已终结未清理任务）；代理登记自提 task_id、判满前逐条核实，`GET /v1/direct/generating-count` 的 `generating`＝核实后真实占用（`platformCount`＝平台原始计数仅兜底外部任务，fail-closed）。"假满"会在一个刷新周期内自动核实解除。多个 submit 进程并行不需要文件锁——代理容量闸门是最终仲裁（429 不建任务不扣分，执行器把该账号本地标满、单元放回队尾）。
- **调度本地记账（V25）**：查一次全池要 13–16 秒而单条提交仅 ~5 秒，故启动查一次，之后提交成功本地 +1（只增不减，只会少提交不会超限），本地判满才真刷新。挑"低于上限且在渲最少、并列时余额多"的账号，打印 `ROUTE unit=N → main-c (在渲 4/5, 余 1925 分)`。
- **账号两层（V30）**：主账号→子账号（当前 2 主 15 子）。整集大批量一律 `--main-accounts all`（自动把 `--accounts` 视为 all）；只给 `--accounts all` 不给 `--main-accounts` 只摊到默认主账号。每子账号积分与渲染额度各自独立；preflight 的 BUDGET 是池合计，账本每条记实际落到哪个"主账号/子账号"。
- **poll 按单元路由**：账本逐单元记 `main_account`＋`account`，轮询各自路由（poll 不需要也不接受账号参数）；手工 curl 要带 `?main_account=&account=`。切账号一律走直连接口（`POST /v1/direct/accounts/{name}/activate`），**不要用网页 `account --use`**（曾出过把 main-a 任务列表当 main-b 汇报的事故）；每条任务显式传 `--account`。
- **排队与时长（V26）**：判断吞吐只能看产出（`vid` 出现的时间戳），不拿 `generating` 当进度；繁忙时段实测提交到出片约 49 分钟（低负载约 6 分钟），排队期间 `render=2`＋`updatedAt` 不变是排队不是卡死，不要据此重投。排队时段仍守本地节流阀。
- **续跑与外部任务**：submit 中途断了用 `--resume` 续跑同一账本；绕过执行器手工直投的任务必须立刻补记账本（`task_id`/`account`/来源），否则 `--resume` 重复提交扣分（V26）。
- **一条龙**：`submit --watch` 提交完自动进入轮询下载（V32）；`unknown_outcome` 停批时不进入轮询（V20 人工核实优先），已提交单元照常在渲、事后手动 `poll` 收片。
- **多集并行占槽溯源（V35）**：全部批次共用同一池（15×5=75 槽），"显示满但我没提交这么多"多半是别的批占的；submit 开工回显其他批警告，POOL/THROTTLE 带归属拆解 `（本批N｜其他集N｜账本外N）`——"账本外"多为失败任务僵尸计数（平台释放约延迟 2 分钟），等待即可。随时查：`python 工具/symphony_video_batch.py stats`（V33，纯本地扫账本；一集完结删 `tasks/{集号}/` 会连带减少当日计数）。

### D. 四步操作

```bat
:: 0. 起代理（双击也行）
工具\symphony\启动代理.cmd

:: 1. 预检——不花钱，核对模型表/许可证/登录态/挂载/时长/总积分，并报本批有几张图未入库
python 工具/symphony_video_batch.py preflight --story-root stories/29-xxx ^
    --prompt-file 分镜-15秒/分镜提示词.md --units 1-12 --model "Dreamina Seedance 2.0"

:: 1.5 预检报 SILENT no 就先热预存——不花钱
python 工具/symphony_video_batch.py warmup --story-root stories/29-xxx ^
    --prompt-file 分镜-15秒/分镜提示词.md --units 1-12

:: 2. preflight 通过后直接提交（--confirm-credits＝BUDGET 数字，执行者自填；整集批量加 --main-accounts all；断了加 --resume 重跑）
python 工具/symphony_video_batch.py submit --story-root stories/29-xxx ^
    --prompt-file 分镜-15秒/分镜提示词.md --units 1 ^
    --model "Dreamina Seedance 2.0" --confirm-credits 15 ^
    --ledger 工具/运行垃圾/tasks/29/symphony-29-U1.jsonl

:: 3. 轮询下载（可反复跑，已下好的单元跳过）
python 工具/symphony_video_batch.py poll --story-root stories/29-xxx ^
    --prompt-file 分镜-15秒/分镜提示词.md ^
    --ledger 工具/运行垃圾/tasks/29/symphony-29-U1.jsonl
```

成片落 `分镜-15秒/成片/{N}单元-{通道}.mp4`（{通道}按实际生成渠道命名，不再固定 symphony）。

### E. 状态判定与失败处理

轮询读 `GET /v1/direct/tasks/{task_id}`：
- **成功** = `assetId` 非空且 `hasContent` 为真 → `POST /v1/assets/{assetId}/download` → ffprobe 验分辨率（V21）。
- **失败** = `error` 字段非空（`generateErrorMessage`/`failReason`/`errorMsg` 任一）→ 原样记账本，不臆测触发项（V15）。
- `renderTaskStatus`/`draftTaskStatus` 数值枚举未穷举，**不按数字判生死**。

| 症状 | 处理 |
|---|---|
| 连不上 127.0.0.1:8765 | 代理没起。跑 `启动代理.cmd`；停代理要杀 **python** 进程（杀 uv 外壳杀不掉子进程） |
| 503 `direct_unavailable` | 登录态过期，重采集 `direct-session` |
| 403 `license_*` | 许可证过期/未激活 |
| **502 `direct_outcome_unknown`** | **V20：整批停止**，可能已扣分；人工去平台 generations 列表确认后再决定 |
| 422 `Reference file does not exist` | 挂载路径打错或图还没生成 |
| **400 `code 10001303`** | **V24：确定性拒绝，没建任务没扣分。不停批**，记 `rejected` 继续 |
| **400 `code 10001114`** | **V29：子账号当日上限（实测每子账号每天 30 条），没扣分不是内容问题**。记 `account_limited` 写盘日限标记（`工具/symphony/data/账号限制.json`），改投其他账号；标记次日早8点自动失效 |
| 疑似公众人物 / 审核失败 | 平台审核拦截，积分会退。改措辞或换参考图重投，计入 V14 上限 |
| 下到 360x640 | V21：播放转码流不是原片，判失败重下 |

**400 与 502 必须分清（钱的问题）**：400+平台业务码＝创建前就拒了、一分没扣，批次继续；502 `direct_outcome_unknown`＝结果不明可能已扣分，整批停止＋人工对账（V20）。

**未成年人触发项（已实测）**：触发源是儿童参考图本身不是提示词文字（文字全替换仍拒，撤参考图后过审）；🚫 任何时候不得为过审撤人物参考图（人物一致性是质量底线）；素描头参考图只过提交关卡不过成片审核（实测良率仅 21%），不构成经济解法。**2026-09-03 用户裁定：不因此在选题/成稿阶段规避儿童角色**——被拒单元走 /xiufu 未成年触发分支（叙述层去龄化重投 → 仍拒则素描头参考图重投，计入 V14 上限、按约 50% 良率排产），或 /zichan 阶段预置素描头资产备用。完整实测数据见 `归档/视频生成实测记录-20260803.md`。

### E1. 人脸/参考图隐私触发——先派生彩铅，再重投（V34）

仅当平台原始错误明确出现 `InputImageSensitiveContentDetected.PrivacyInformation`、`face detect not pass` 或同义人脸/参考图隐私拒绝时进入本分支；普通 `video audit rejected`、网络/503、`direct_outcome_unknown` 不得套用。

1. 保留失败任务的原始响应、任务号、账本终态及费用/退款状态；按当前单元"视频挂载"与"图片N"顺序建立角色 ID→精确文件名映射，标出可疑人物参考图。不臆测触发词，不删人物参考图。
2. 只对确认的可疑图处理：从同角色同状态写实人物设定图单张图生图派生新彩铅参考图，固定走 `flow2api_banana2`/`gemini-3.1-flash-image`，固定提示词「不改变图片，把图片风格转换成素描彩铅画」，9:16、1K；旧图不覆盖，文件名带 `face-rederive-vN`。
3. 技术核对（存在/数量/命名/可打开/尺寸）→ warmup 入直连缓存 → 重新 preflight，按剩余额度与已确认退款逐笔核算重投预算。
4. 只替换受影响单元的精确挂载、只重投已确认失败单元；新任务与下载文件带版本名，重投计入 V14 上限。账本或远端结果不确定时先人工对账。

### E2. 成片审核失败（`video audit rejected`）

操作纪律见 V27（约50%良率估投入／失败重投计入V14上限／积分退款逐笔对账不得用余额反推）；失败集中在少数单元且反复不过时，走 V13 首帧图生视频或换通道。29 集约 48% 失败原因至今未知，实测数据见 `归档/视频生成实测记录-20260803.md`。

### F. 本机配置

`工具/symphony/symphony配置.json` 是本机路径唯一来源（端口、OpenCLI 入口、node、ffprobe、默认子账号），换机器只改这一个。**改端口必须同步改 `工具/api配置.json` 的 `providers.symphony_video.base_url`**——`launch.py` 启动时比对并告警。

## 五、任务账本、下载与验收边界

### 1. 任务账本

**路径固定 `工具/运行垃圾/tasks/{集号}/`**（任务账本、请求/响应体属可删中间件，禁放 stories/ 与 成片/），命名带平台与单元号（如 `symphony-29-U1.jsonl`）。每次成功创建任务后立即 JSONL 追加并 flush：
- 通用：`platform`、`unit`、`model`、`submitted_at`、最后状态、输出文件路径
- Symphony：`task_id`、`duration`（＝扣的积分）、`account`、`backend`、`asset_id`、`resolution`；提交失败记 `status: submit_failed`，结果不确定记 `status: unknown_outcome`＋原始错误（V20 人工确认依据）
- Canvas/Guagu 字段见 备用通道文件

账本禁写 API 密钥、完整 prompt、data URL、`asset://`、签名下载 URL。状态判定按单元取最后一条（V28）。

### 2. 下载与编码

1. 成功后立即下载原片到本集 `成片/`，下载 URL 不写长期日志。
2. ffprobe 检查编码、分辨率、帧率、时长、文件非零。
3. 原片为 HEVC 时保留为 `{N}单元-hevc原始.mp4`，再用 `libx264 + yuv420p + AAC + faststart` 转 `{N}单元.mp4`；已是 H.264 直接落最终文件。
4. 最终核对 H.264、AAC、竖屏分辨率、时长与单元参数相符；平台客观不支持时以用户重新确认的参数为准并在账本标注。
5. 不覆盖旧成片；重跑先带版本号或平台后缀落盘，用户选定后再整理最终名。

### 3. 验收边界

执行者只做技术性核对并把路径清单交用户：任务成功、文件存在、数量、命名、格式、编码、尺寸、时长。不得主动播放评价同脸、构图、动作、口型或擅自重跑；用户点名或调用 /xiufu 后才检查指定产物。

## 六、失败处理与回退方案

1. 先保存平台原始状态、错误码和错误文本，再判断是参数、素材、模型能力、内容审核、网络还是计费问题。不把修复记录或错误文字拼进下一次 prompt。命中 V34 先走 E1 分支。
2. 接口只返回笼统拒绝时，只能确认被拒，不能区分"真人照片限制"与"内容审核失败"——报告原文和信息边界，不臆测触发词（V15）。
3. 参数错误先本地修正；模型能力不匹配、下架或需跨平台时，重新查全部已配置 provider 的模型表并让用户确认。
4. 同一单元连续失败2次，可启用 V13 回退（首帧图生视频）：按该单元提示词生成一张写实首帧图（人物、产品、场景参考融合，产品参考必须参与），用户审核通过后只挂该图生成视频。台词、时长、剧情、镜头顺序不删。
5. 单元最多重跑3次。到上限停止计费尝试，报告各次平台、模型、任务号、费用状态和失败原因，交用户决定拆单镜、砍同框角色或换方案（V14）。

## 七、批量生成操作顺序

1. 核验 `fenjing_ready` 或用户点名清单。
2. 默认 Guagu，不再询问平台；按 §一.3 核对实时目录与本批已选完整模型，尚未选模型时先选择，再按 §一.2 做 preflight，通过后按已授权范围执行。
3. 读取当前分镜并完成 prompt 边界、挂载顺序、文件、参数与预算预检（§二）。
4. 预检通过后对无依赖单元执行全量任务（无单条测试关卡），按平台节流阀分批提交，提交即写账本。
5. 轮询、下载、转码和技术核对；只交付路径与任务汇总，不替用户做画面验收。
6. 用户反馈翻车单元时进 `/xiufu 单元号 现象描述`，或按 V13 回退首帧图生视频。
