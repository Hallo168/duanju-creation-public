## 第一步 · 字幕对齐（规范 §一）

```powershell
python 工具/字幕提取.py "<草稿名>" "工具/运行垃圾/tasks/{集号}/字幕导出.tsv"
```

加密草稿直接读，**不用再手动降级**（C8）；只有要人眼看 JSON 时才 `python 工具/剪映/草稿降级.py <草稿名>`。

逐条对照台词基准（C1：二创稿为底，被 /xiufu 改过的单元以分镜提示词最新版为准）产出修正 tsv，重点过 C4 四类错型（同音人名要全局搜变体）。回写：

```powershell
python 工具/字幕回写.py "<草稿名>" "工具/运行垃圾/tasks/{集号}/字幕修正.tsv"
```

**字幕没对齐就不能配乐**——下一步的单元定位全靠它。

## 第二步 · 配乐音效（规范 §二）

```powershell
python 工具/配乐/草稿时间轴.py "<草稿名>" --fenjing "<分镜提示词.md>" --out "工具/运行垃圾/tasks/{集号}/时间轴.json"
```

先看**对齐质量**：`字幕匹配率`／`台词覆盖率` 低于 0.95 或 `缺席单元` 非空 → 回第一步，别在错位的时间轴上配乐。

**对白参考音频**：整集 mp4 直接用；只有分单元成片时，按序拼接再按草稿倍速拉伸对齐时间线（§2.1 给了 22 集的实例）。

**然后执行“双读”**（M16）：

1. 通读时间轴 JSON 的 `字幕` 字段（按单元分组），抽出实际对白时间及“欲望—阻力—信息差—证据—关系反转—情绪落点”。
2. 逐单元通读 `分镜提示词.md` 的完整 `### 单元提示词`，不是只看分镜总表；提取镜头/场景切换、运镜、动作帧、人物停顿、光影、道具状态，以及 `<音效>` 中已经随视频生成的声音。
3. 先写 `工具/运行垃圾/tasks/{集号}/配乐镜头对照表.md`：`单元｜时间｜台词因果｜关键镜头/动作｜原生音(<>)｜BGM任务｜音乐性音效落点`。每个换乐点和音效点必须有画面依据；已有同源原生音不重复叠加。实际对白内容和时间以草稿时间轴/参考音频为准。

镜头对照表通过自查后，再写 `工具/运行垃圾/tasks/{集号}/配乐段落表.json`：BGM 段落＋音乐性音效，`环境` 固定为空数组；**音量一个都不填**（M5，脚本按响度反算）：

```json
{
  "草稿": "...", "时间轴": "...", "对白音频": "...", "输出目录": "工具/运行垃圾/tasks/{集号}",
  "段落": [{"label": "开场旧债压心", "起单元": 1, "类型": "压迫", "曲目": "BGM/开场紧张场景配乐类背景音乐.mp3"}],
  "环境": [],
  "音效": [
    {"label": "开场提出疑问·一咚", "绝对时间": 0.0, "文件": "音效/咚咚.mp3", "类型": "爆点"},
    {"label": "证据揭晓·悬念上扬", "绝对时间": 438.73, "文件": "音效/蓄势-悬念上扬-Mixkit.wav", "类型": "氛围"}
  ]
}
```

- `段落`：按**三段式骨架**铺（0秒定调锤＋BGM晚进→刻意静默段→主床一铺到底→结尾三收法，2026-08-07 五稿版），整集通常 3–5 段＋1–3 处静默；`类型`／`起单元` 取值规则见 后期规范 M2–M4/§2.2。
- `环境`：固定 `[]`（两层制不配环境音，细则见 CLAUDE.md「两层制」裁定与 后期规范 §2.4）。
- `音效`：只用音乐性音效、不补动作拟音；按**五族映射**打点、数量无上限（M9/§2.4）；禁用素材见 后期规范 §2.2。

```powershell
python 工具/配乐/配乐方案生成.py "工具/运行垃圾/tasks/{集号}/配乐段落表.json"
```

每条 `[提醒]` 都要处理或说明理由（曲子不够长会听出续铺重启；音量被夹住说明素材够不到目标电平，换素材别改 Δ）。

## 第三步 · 封面与发布文案（规范 §三）

按 §3.1 生成封面（图生图挂本集写实人物设定图，3:4）、按 §3.2 写 `发布文案.md`。简介以**分镜最新剧情**为准（F6）；**不带话题标签、简介只写一行 4–8 字剧眼短语**（F7，2026-08-01）。封面生成后只报路径与技术性落盘结果，**不看图、不评价**（F4，宪法硬规则）。

这一步与第二步互不依赖，可以在等音频渲染时并行做。

## 写盘授权（2026-07-27 用户裁定）

用户调用 `/houqi` 即视为授权把后期音频直接写入草稿，**不再把字幕结果、配乐方案、封面与文案先交用户过目，也不再询问“是否写盘”**。方案生成后连续执行第四步；写完再把字幕、配乐方案、封面与发布文案一次性交用户试听/审图。用户试听反馈后按同名轨替换重写。

## 第四步 · 写盘与验证（规范 §2.5）

```powershell
# 先扫现有音频轨（M13）
python 工具/剪映/写入音轨.py "<草稿名>" --scan
# 校验
python 工具/剪映/写入音轨.py "<草稿名>" "<配乐方案.json>" --dry-run
# 逐条轨写：BGM → 音乐性音效 1..N（每条轨一次）
python 工具/剪映/写入音轨.py "<草稿名>" "<配乐方案.json>"
python 工具/剪映/写入音轨.py "<草稿名>" "<音效方案-1.json>"   # 2..N 同理
```

- 要清掉的旧轨**用 `replace_track_names` 按名字点名**，不要用序号（M13，序号会被同批的前一次写入改掉）；
- 写完**先看 `encrypted_draft`**（M14.1）：加密草稿写成明文会静默失败——剪映照常打开、视频字幕都在，只有音轨整条不出现且不报错。核一下首字节，加密草稿写完不该是 `{`；
- 过完 M14 验证清单 0–4 项（试听归用户）；
- **用户在剪映开过草稿之后，回来要再 `--scan` 一次**：剪映会静默吞掉同轨重叠的音效段（M14.2，22 集实测被吃掉 4 个）。
