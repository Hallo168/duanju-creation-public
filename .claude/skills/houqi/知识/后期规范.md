# 一、字幕对齐（C1–C8）

> 环节：剪映"识别字幕"自动生成之后。

## 清单

- **C1** 对齐基准=实际进片的台词最新版：二创稿为底，被 /xiufu 或分镜阶段改过台词的单元以分镜提示词.md 修复后版本为准 → §1.1
- **C2** 字幕跟实际语音走：录音漏说/跳过的句子**不强行插入稿件全文**，只修实际说出部分的错字与标点——字幕必须与耳朵听到的对得上 → §1.1
- **C3** 用户发出"对齐字幕"即视为已关闭目标草稿，执行者**不再检测剪映进程、窗口或草稿是否打开，不重复询问确认**；回写脚本自动备份 `draft_content.json.pre_subtitle_fix.bak`（重复运行覆盖旧备份，要留多版先改名）；写完由用户在剪映重开草稿抽查首/中/尾各几条 → §1.2
- **C4** ASR 高频错型四类逐项过：同音人名、同音别字、全程无标点、跨句错切；**人名用错字变体全局搜一遍兜底**（一处人名错型往往全片重复出现）→ §1.3
- **C5** 文本本体在 `materials.texts[].content`（嵌套 JSON 字符串）：改 `text` 必须同步改 `styles[].range=[0,新文本长度]`，`base_content` 同改；`recognize_text` 是识别原始记录，保留不动 → §1.4
- **C6** 段序按全部 text 轨合并后 `target_timerange.start` 升序对位；只动 `type=="subtitle"` 的素材（压屏字幕/标题/贴纸不碰）——提取与回写必须用同一排序，序号是唯一对位键 → §1.4
- **C7** JSON 读写一律 UTF-8、`ensure_ascii=False`；回写前先校验修正条数=草稿字幕条数（对不上不写盘），写完重新 `json.load` 验证合法（宪法 12 编码坑同源）→ §1.4
- **C8**〔2026-07-27 更新〕加密草稿**不再需要手动降级**：字幕提取/回写与配乐写盘都走 `工具/剪映/环境.py`，明文密文都读、并按原格式写回。人要直接看 JSON 或用外部工具时，才跑 `python 工具/剪映/草稿降级.py <草稿名>` 降成明文（`--状态` 看格式，`--升级` 加密回去，均自动备份）→ §1.4

## §1.1 对齐原则

**基准的选取（C1）**：字幕校对的"正确答案"是演员（AI 配音）实际念的台词，其底稿链条是：二创稿 → /fenjing 套符号 → /xiufu 修复改词。所以：默认拿二创稿正文逐段对；该单元有修复记录（v2/v3…）且改动涉及台词的，以分镜提示词.md 的最新版为准；两边都对不上时，以实际音频为准。

**字幕跟语音走（C2）**：04 集实测发现 3 处录音跳过了稿件里的个别句子（在时间轴上没有对应片段、时长也装不下）。判定方法：该句在字幕时间轴上无对应片段、或相邻片段时长明显容不下该句字数。处理：**不补插稿件全文**，只把实际说出的部分修正措辞和标点。理由：字幕和语音对不上比字幕少一句更伤观感。

**标点要补全**：ASR 输出几乎无标点。逐条按台词稿补回问号/感叹号/破折号/引号——字幕的情绪节奏靠标点传达。

## §1.2 操作流程

1. **提取**：`python 工具/字幕提取.py "<草稿目录>" <导出txt>`——得到「序号\t开始μs\t时长μs\t文本」清单
2. **对词**：agent 逐条对照台词基准（C1），产出修正 txt（每行「序号\t修正文本」；没错的行原样保留，序号必须全量连续——回写脚本按条数校验）
3. **关草稿（用户前置负责）**：用户发出指令即视为已关闭（C3）
4. **回写**：`python 工具/字幕回写.py "<草稿名>" <修正tsv>`——自动备份、覆写**根目录与 Timelines 两份**、回读验证
5. **人工抽查**：剪映重开草稿，抽首/中/尾各几条核对样式未坏、文本正确

## §1.3 ASR 错型档案（04 集实录）

| 错型 | 04 集实例 | 排查手法 |
|---|---|---|
| 同音人名 | 晓禾→"小何"、静仪→"静怡"、程远舟→"程远洲/远周/陈远忠" | 每个角色名列出同音变体，全局搜（一种错型全片重复） |
| 同音别字 | 瘫子→"摊子"、厂子→"肠子/场"、潮气→"晌气"、樟脑丸→"掏挠丸"、跑得→"跑的"、比布贵→"笔不贵"、眼拙→"眼脏"、捎给您→"烧给您"、见客→"剑客" | 逐条对台词稿，重点盯名词和方言词 |
| 无标点 | 全部 297 条 | 按台词稿逐条补 |
| 跨句错切 | "戏 / 要真，先瞒 / 屋里人"被切进三条相邻字幕 | 不动时间轴，把文本按实际切点重新分配到相邻字幕卡（每卡文本与该卡语音对上即可，句子跨卡不算错） |

数字写法：ASR 出阿拉伯数字（"80万/9块9"），台词稿是汉字（"八十万/九块九"）——统一改回台词稿写法，与 `{}` 内文字逐字一致（样式设置见本文件「附录·字幕样式模板」）。

## §1.4 draft_content.json 结构备忘

- 草稿位置：`<剪映草稿根目录>\{草稿名}\draft_content.json`（单文件 1MB+ 属正常）；时间单位 **微秒（μs）**
- 字幕素材：`materials.texts[]`，`type=="subtitle"`；`content` 是**嵌套 JSON 字符串** `{"styles":[{...,"range":[0,N]}],"text":"…"}`——改 `text` 必须把每个 `styles[].range` 终点同步为新文本长度；`base_content` 结构相同同步改；`recognize_text` 保留不动；`words` 逐字时间戳不改文本级对齐可不动
- 字幕排序：`tracks[]` 里 `type=="text"` 轨道的 `segments[]`，按 `target_timerange.start` 升序=播放顺序
- 写盘：UTF-8、`ensure_ascii=False`、紧凑分隔符（剪映原格式即无缩进）
- **加密坑（C8）**：剪映 10.7 会在用户重开草稿保存后把 `draft_content.json` 与 `draft_meta_info.json` 加密重存（文件头变乱码、体积变大，同目录 `crypto_key_store.dat` 即密钥库）。**本项目的脚本明文密文都读、并按原格式写回**（2026-07-27 独立化之后，字幕与配乐都走 `工具/剪映/环境.py`）；只有人要直接看 JSON 或用外部工具时才需要 `工具/剪映/草稿降级.py` 降成明文

# 二、配乐音效（M1–M16）

> 环节：字幕对齐**之后**。默认两层声音：BGM 一条、音乐性音效若干条；**不配环境床，不配写实拟音**。

## 清单

- **M1** 前置三件事齐了才开工：成片已拼接进草稿、字幕已按 §一 对齐、**目标草稿已关闭**；调用 `/houqi` 即授权音频方案直接写盘，不再二次询问 → §2.1
- **M2**〔2026-08-06 对标定稿；2026-08-07 五稿复核升级〕BGM 走**三段式骨架**：①开场段（开场三型见 M11，盖住冷开场压迫/事故戏）→ ②**刻意静默段 1–3 处**（温情/宣告/拷问段整段无 BGM，每处 7–30s）→ ③中段主体**主床一铺到底**（1.5–4 分钟不换曲，情绪起伏交给音效标点）→ ④结尾按情绪落点收（M4 三收法）→ §2.2
- **M3** BGM 进出点对齐**情绪句**，不对齐场景切点：开场曲不从 0:00 进、默认第 3–4 句台词处进（约 5–7s，高动作冷开场可裸奏到 24s 再进）；静默后音乐**精确进在情绪升级句上**（绝望宣告/泪点转折/答案揭晓）；出点贴换场前 0.5–1s，缝由转场音效填。段数跟内容走，五稿实测整集 3–5 段 BGM＋1–3 处刻意静默（同曲跳源点续铺不另计段；旧 6–10 段制 2026-08-06 废止）→ §2.2
- **M4**〔2026-08-07 升级〕结尾按情绪落点收，**三收法**：**高燃收**——同曲跳副歌续铺＋音量抬约 50%（稿0），或换高燃曲＋音量明显抬高、直进不淡入、钉在质问爆点句上（稿2《Rise》）；**温情收**——升华/柔曲软进直到片尾，不抬不炸（稿1《救赎之光》、稿3《柔和之光》）；**静默收**——清算完成后 BGM 提前退场，最后感言/升华段裸奏到片尾（稿4 尾段 28s）→ §2.2
- **M5** BGM 音量**不许手填**：`volume = 10^((该段对白LUFS − Δ − 曲目LUFS)/20)`，Δ 见 §2.3 表。手填数字会因曲目自身响度差 7.5 dB 而听感乱飘（实测）→ §2.3
- **M6** 口播带货段 Δ 取 18（压得最狠），打脸爽点段 Δ 取 10（放得最开）——爽感差别靠 Δ 表实现，不靠换曲子 → §2.3
- **M7** 音效走**峰值口径**：`volume = 10^((对白峰值dBFS + Δ音效 − 素材峰值dBFS)/20)`；音量被夹到 1.0 = 素材本身太肉，换素材不要硬调 → §2.3
- **M8** 默认只配**音乐性音效层**，环境床和动作拟音默认禁用，细则见 §2.4
- **M9**〔2026-08-06 对标定稿；2026-08-07 五稿复核〕音效按**五族映射**打点（咚族定调/重锤、转场闪光、水滴族、紧张悬疑刺点、带货段零音效，映射表见 §2.4），另有**素材原声刺点**手法（高动作场面直接截素材自带声音当刺点）；**数量无上限**——跟着情绪标点走，有一个点打一个（五稿实测约 1–2 次/分钟是内容长出来的结果，不是指标；旧「同素材 ≤3 次」「Mickey Mousing ≤3 处」等一切次数限制 2026-08-06 用户裁定废止）→ §2.4
- **M10** 打脸/清算段：刺点音效打在清算开场句**前一拍**；BGM 不骤停、不留静默；刺点可与换曲接缝/同曲跳源点重合互相遮盖（旧「切断→静默→爆点→新段」四步 2026-08-06 废止，对标未用）→ §2.4
- **M11**〔2026-08-07 二轮，用户裁定〕开场 0 秒**固定配定调锤**「综艺开头-咚（空旷）」——每集默认打上，方案不做取舍，用户试听后按实际情况自行删调。BGM 进场两型：默认**第 3–4 句台词处直进**（约 5–7s，稿0/1/2/4）；高动作救援/事故冷开场靠素材原声撑 15–25s、在戏剧定调句处进（稿3 至 24s）。共同点：**BGM 一律不从 0 进、不淡入**；选曲要求快进主旋律，长前奏用索引「建议起点」跳过 → §2.4
- **M12** 提示词里写过 `<>` 的动作同源音（拍桌/耳光/椅响，`提示词规范.md` T17）**不重复叠**；后期只补剧本情绪因果需要的音乐性音效，不补动作拟音 → §2.4
- **M13** 写盘前必跑 `--scan` 看现有音频轨：剪映重存会抹掉轨道名，同名替换会失效；旧轨优先用 `replace_track_names` **按名字**点名，序号是位置、会被同批的前一次写入改掉 → §2.5
- **M14** 写盘后逐条过验证清单（**格式**/轨数/路径/首尾/接边/试听），异常回滚 `.backup/autotool_bgm_*` → §2.5
- **M14.1** 加密草稿写回必须仍是密文：写成明文时剪映照常打开、视频字幕都在，**只有音轨整条不出现且不报错**——写完必看返回里的 `encrypted_draft` 并核对文件首字节 → §2.5
- **M14.2** 同一条音轨上相邻两段之间必须留 ≥10ms 间隙：**哪怕只重叠零点几毫秒，剪映下次打开保存时会静默吞掉其中一段**（2026-07-27 22 集实测，四舍五入误差吃掉 4 个音效，无任何报错）。生成脚本已按毫秒向下取整并留 `LANE_GUARD=0.01s`；用户在剪映开过草稿后，**回来要重扫一次段数对不对得上旁证清单** → §2.5
- **M15** 合规：曲目必须在 `配乐库/索引.md` 有来源与许可记录（Pixabay 记作品页＋许可页）；剪映曲库素材**可用**（2026-08-06 用户裁定，来源记「剪映音乐库」，限剪映/抖音生态内发布，站外分发另行确认许可）；AI 生成声明照旧勾 → §三·F5
- **M16** 配乐设计必须“双读”：字幕时间轴＋每个单元完整的 `### 单元提示词`。台词管真实语音时间与情绪因果，分镜管镜头/场景切换、动作帧、停顿、光影、道具状态及提示词内置 `<音效>`；BGM 同时服从剧情因果与镜头段落，音乐性音效必须落到具体画面，并避开同源声音重复 → §2.1/§2.2/§2.4

## §2.1 前置与输入

1. **成片已进草稿**：草稿里视频轨通常是「复合片段」，拿不到单元边界——这是必须靠字幕对齐的原因。
2. **字幕已对齐**：对齐质量直接决定单元定位精度；匹配率需接近 100%，低于 95% 先查台词稿版本。
3. **草稿已关闭**：同 C3，不检测进程、不重复询问。
4. **写盘授权随命令成立**（2026-07-27 用户裁定）：`/houqi` 一旦发出，生成方案后直接执行 `--scan`、`--dry-run`、逐轨写入与 M14 验证，不再把“是否写入音轨”作为中途确认问题。

**对白参考音频**：量响度要一条与**时间线对齐**的音频。成片已导出整集 mp4 的直接用；只有分单元成片时，把单元按序拼接后按草稿倍速拉伸（22 集实测：复合片段 0.85x 慢放，源 628.09s → 时间线 738.93s，用 `atempo=0.857875` 拼出的参考音频与草稿只差 0.02s）。不做这一步，后半段的音量会按错位的对白电平算。

输入文件：草稿目录、本集 `分镜-15秒/分镜提示词.md`、对白参考音频、`配乐库/索引.json`。

**双读工作法（M16，2026-07-29 用户裁定；26 集逐镜重配试听确认可行）**：

1. 先把时间轴 JSON 的 `字幕` 按单元通读，抽出欲望、阻力、信息差、证据链、关系反转和情绪落点；这里决定“观众此刻听懂了什么”和实际语音时间。
2. 再逐单元读 `分镜提示词.md` 的完整 `### 单元提示词`，不能停在分镜总表；提取场景/镜头切换、运镜、人物与道具动作、停顿、光影变化，以及 `<音效>` 中已经随视频生成的原生声音。
3. 先写 `工具/运行垃圾/tasks/{集号}/配乐镜头对照表.md`，至少包含：`单元｜时间｜台词因果｜关键镜头/动作｜原生音(<>)｜BGM任务｜音乐性音效落点`；每个换乐点和音效点都必须能在表中找到画面依据，再生成 `配乐段落表.json`。
4. 对白与分镜文字不一致时，实际对白内容和时间以草稿时间轴/参考音频为准；分镜只用于定位已经存在的画面落点，不把声音硬塞到成片里没有的动作上。

## §2.2 BGM 三段式骨架（2026-08-06 对标定稿；2026-08-07 五稿复核升级，主方案）

## §2.3 音量制（核心）

**为什么不能手填**：曲目自身响度差达 7.5 dB，同样的 `volume` 数值压在不同曲子上听感差一个数量级（实测，2026-07-27）——音量必须从响度反算。

**BGM 公式（M5）**：`目标电平 = 该段对白LUFS − Δ`，`volume = 10^((目标 − 曲目LUFS)/20)`，夹在 0.02～1.0。

| 段落类型 | Δ(LU) | 用在哪 |
|---|---:|---|
| 打脸 | 10 | 打脸爽点、反转清算 —— 放得最开 |
| 蓄势 / 片尾 | 12 | 反转前蓄势、压迫顶点、结尾升华 |
| 压迫 / 悬疑 | 13 | 反派施压、猜疑、争执升级 |
| 回忆 / 低谷 / 温情 | 14 | 煽情、绝望、认亲和解 |
| 对白 | 15 | 常规对白推进（默认档）|
| 口播 | 18 | 带货口播、产品展示 —— 压得最狠 |
| 过场 | 8 | 无台词的纯动作/空镜段 |

**起点值，首集实听后回校。**

**音效公式（M7）**：短音效不足 3 秒时积分响度不可靠（EBU 门限吃掉），改用峰值：`volume = 10^((对白峰值dBFS + Δ音效 − 素材峰值dBFS)/20)`。Δ音效：爆点 0／强调 −8／桥接 −6／氛围 −12。

**被夹住就换素材**：脚本报「音量被夹到 1.0」= 素材本身电平够不到目标，硬调只会更肉。

## §2.4 音效五族映射（2026-08-06 对标定稿，主方案）

**五族映射表（什么话配什么音效）**：

| 族 | 素材（配乐库/音效/） | 打在什么话上 | 位置 |
|---|---|---|---|
| **咚族（定调/重锤）** | 综艺开头-咚（空旷）／开场音效咚 | 0:00 开场定调（**每集固定配**，M11，用户可删调）；中段质问重锤（『管理员账号是你的』）；**静默段中的揭露句**（『1800一个月』）；可盖换曲缝（稿2 265s 咚桥进《Rise》） | 定调钉 0:00；重锤打在揭露/质问句**前一拍** |

**素材原声刺点（2026-08-07 稿3 新手法）**：高动作场面（救援嘈杂、关键呼喊『芳姐我终于找到你了』）直接从视频素材截 0.7–3s 自带声音、抬到音效音量当刺点用——原声比库音效更贴画面。裸奏冷开场（M11-C）主要靠它撑住声场。集特定素材不入库。

**转场三件套**：跳时间/换地点＝高音闪光转场＋打字机花字（『五天后…』『医院里…』）＋打字（字幕专用）音效，三者同点位。打字音效**只配时间地点花字**，促销花字（『5罐39块9更划算』）不打。

**视觉配套（2026-08-07 对标补测，五稿 18 处闪白复核）**：视觉转场只用剪映**「闪白」**一种（0.7–0.8s），不混叠化/划像。配对规律：**闪白必配声音事件**——18 处闪白里 15 处配闪光音效（音效**提前 0.4–0.75s 先响**、闪白跨在剪切点上，听觉预告→视觉兑现）、1 处配综艺当当当当（变脸装相点）、1 处盖 BGM 进场（二胡曲随闪白进）、仅 1 处裸用。反向不强制：闪光音效约 1/3 无闪白（素材内叙事换场、情绪揭晓句）。转场特效由剪辑者在剪映端手动加（音频流水线不写视觉层），配乐镜头对照表的换场点注一句「配闪白」提醒。

**数量（M9）**：**无上限**（2026-08-06 用户裁定，废止旧 ≤3 类限制）。判据只有一条：这句话是不是情绪标点——是就打，不是就不打。对标密度约 2 次/分钟是内容长出来的结果，不是指标。

**打脸/清算段（M10）**：刺点音效打在清算开场句前一拍；BGM 不骤停、不留静默；刺点可与换曲接缝/同曲跳源点重合互相遮盖（对标：『工伤保险也一天没给你买过』的紧张转场音效直接桥进《救赎之光》换曲点）。

**开场（M11）**：0 秒定调锤；BGM 第 3–4 句台词处进、不淡入；长前奏按索引「建议起点」跳过——竖屏观众 1–3 秒内决定去留。

**动作帧类爆点**：确需卡动作的音效（掌掴/摔杯）仍卡在**动作发生那一帧**（误差 ≤1 帧／33ms）；台词触发的落点放在**最后一个字说完后的停顿**里，给观众半拍消化。

**重叠自动拆轨**：一条剪映音轨上的段落不能重叠。故意要叠的组合由生成脚本按“第一条空着的轨”自动拆成 `SFX-1/2/3…`，不要为了避让把素材剪短。

**双读（M16）照旧**：每个音效点必须能在配乐镜头对照表里找到台词/画面依据。

## §2.5 执行与验证

```powershell
# 1. 导时间轴 + 单元对齐
python 工具/配乐/草稿时间轴.py "<草稿目录>" --fenjing "<分镜提示词.md>" --out "工具/运行垃圾/tasks/{集号}/时间轴.json"

# 2. agent 双读字幕时间轴 + 每单元完整分镜提示词，先写镜头对照表，再写段落表
python 工具/配乐/配乐方案生成.py "工具/运行垃圾/tasks/{集号}/配乐段落表.json"

# 3. 写盘前先看现有音频轨（M13）
python 工具/剪映/写入音轨.py "<草稿名>" --scan

# 4. 校验不写盘
python 工具/剪映/写入音轨.py "<草稿名>" "<配乐方案.json>" --dry-run

# 5. 逐条轨写：BGM → 音乐性音效 1..N（每条轨一次）
python 工具/剪映/写入音轨.py "<草稿名>" "<配乐方案.json>"
python 工具/剪映/写入音轨.py "<草稿名>" "<音效方案-1.json>"    # 2、3… 同理
```

**重跑幂等的坑（M13）**：剪映重新保存草稿会把轨道重写成自己的精简结构，**自定义轨道名被抹掉**（21 集实测：`BGM-剧情分段` 变成 `is_default_name: true`、无 name）。所以：

- 脚本会在草稿目录留 `.autotool_bgm/manifest.json`（剪映不动它），下次靠"音频文件集合＋段数"指纹认轨；
- 要清掉的旧轨**用名字点名**：`"replace_track_names": ["旧轨名"]`；
- `replace_audio_track_indexes` 是**位置序号**，同一批里前一次写入会改变轨道顺序——2026-07-27 实测踩坑：拿写 BGM 之前扫出的序号跑音效那步，把刚写好的 BGM 轨删掉了。只有轨道名已被剪映抹掉时才退回序号，且序号必须来自**紧挨着这一步**的那次 `--scan`；
- `--dry-run` 的 `will_replace_tracks` 会回显将被替换的轨，**看清楚再写**。

**加密草稿的坑（M14.1，2026-07-27 21 集实测）**：剪映 10.7 把两份 JSON 加密保存。写回明文的后果是**静默失败**——草稿能打开，视频、字幕、原有音频都在，只有外部写入的音轨整条不出现，不报任何错。写入脚本按整个草稿判断格式并原样加密写回，返回里的 `encrypted_draft` 就是这次用的格式。**这条是当时五项技术核对全过、结果草稿里什么都没有的原因**，所以排在验证清单第一位。

**验证清单（M14）**，写盘后逐条过：

0. **格式**：`encrypted_draft` 与草稿实际状态一致；加密草稿写完首字节仍不是 `{`；
1. `--scan` 复核：BGM 轨、音乐性音效轨各就各位，**没有 AMB 环境轨和动作拟音轨**，没有重复叠加，没有该删没删的旧轨；
2. 所有素材路径存在；
3. BGM 首段按 M3 晚进（不再要求从 0 起）；段间只允许**声明过的静默段**留缝（生成脚本对未声明的缝会报提醒）；最后一段结束点 = 草稿总时长（声明尾段静默除外）；
4. BGM 相邻段衔接正确；音效各轨内部无重叠；
5. **用户在剪映开过草稿之后**：再跑一次 `--scan`，核对各轨段数与旁证清单一致——剪映会静默吞掉重叠段（M14.2）；
6. **用户在剪映试听**：对白清晰度优先，被压就整体调 Δ 表 +2；爽点不够炸就 Δ −2。判定权在用户耳朵。

**回滚**：退出草稿 → 把 `草稿目录\.backup\autotool_bgm_时间戳\` 里的两个 `draft_content.json` 按原相对路径复制回去。同目录 `applied_plan.json` 是当次方案。

## §3.3 发布自查（④）

发布前逐条勾：

1. **AI 生成声明已勾选**（F5，法定强制，不是建议项）；
2. 简介无真实支付平台、社交平台、品牌名（`审稿修改经验.md` 第一节）；简介为一行 4–8 字短语，且**文案里没有任何话题标签**（F7）；
3. 封面文件与标题一致，封面已由用户审过；
4. 字幕按本文件「附录·字幕样式模板」设置到位；
5. BGM 与音效已由用户试听通过，曲目在 `配乐库/索引.md` 有来源与许可记录（M15）；
6. 发布后回填 `数据.md`。
