## 〇、生图执行方式：API 自动生成（2026-07 用户裁定，硬规则）

**/zichan 产出提示词后必须直接调 API 把图生完，不把生图操作留给用户等待。**

**普通资产强制主渠道＝本机部署的 GPTAPI/chatgpt2api（GPT-Image-2，2026-07-16、2026-07-21 用户裁定：免费、并发无上限、多参考图无上限、额度充足）**。**彩铅派生是唯一例外（2026-08-02 用户裁定）**：固定使用 `外部依赖/flow2api` 的 Banana 2（完整模型名 `gemini-3.1-flash-image`），只接同角色同状态写实人物设定图这一张参考图，输出 9:16、1K，提示词逐字固定为「不改变图片，把图片风格转换成素描彩铅画」；不得把彩铅任务静默回退到其他通道或模型。

**人脸触发派生规则（2026-08-03 用户新增）**：Symphony 返回 `InputImageSensitiveContentDetected.PrivacyInformation`、`face detect not pass` 或同义的明确人脸/参考图隐私拒绝时，保存原始错误与任务账本，逐单元把“视频挂载”中的角色 ID 映射到精确文件名，建立可疑参考图清单；不得把普通审核拒绝、网络错误或 `direct_outcome_unknown` 当作人脸触发。对确认的可疑人物图，只从同角色同状态写实人物设定图单张图生图派生新彩铅图，仍固定使用 Banana 2、9:16、1K 和原固定提示词；旧图不覆盖，新图先做技术核对并通过 Symphony warmup，再按剩余实际额度和账本对账结果只重投受影响单元，重跑次数计入 V14 上限。

统一脚本仍为 `工具/gen_grids_multi.py`——普通文生图/参考图生图与彩铅派生共用任务文件超集（`{output_dir, tasks:[{id,file,size,prompt|prompt_file,refs?,provider?}]}`）和拓扑分层；脚本按任务自动分流：文件名含「彩铅参考图」且有 refs，或显式 `provider: "flow2api_banana2"`，即强制走 Flow2API。普通任务固定走 chatgpt2api；彩铅任务服从当前生产开关，启用时固定走 Flow2API，两路均不自动切换通道。
- 跑法：`python gen_grids_multi.py <任务json> [c2a并发]`，普通资产默认并发 `6`；彩铅并发读取其独立配置，启停服从 `工具/生产开关.json`。任务中指定未配置的生图渠道会在提交前终止，不静默改走其他渠道。
- 配置：`工具/api配置.json` 的 `providers.chatgpt2api`（`base_url` `http://127.0.0.1:8000` + `api_key`＝该项目 config.json 的 `auth-key`，端点 `/v1/images/generations` 与 `/v1/images/edits`）
- 彩铅配置：`工具/api配置.json` 的 `providers.flow2api_banana2`；运行时从 `外部依赖/flow2api/config/setting.toml` 只读 API key，项目内不重复保存；调用 Gemini 官方格式 `POST /models/gemini-3.1-flash-image:generateContent`，原图以 `inlineData` 输入
- 同步一步到位：无 refs → `POST /v1/images/generations`（JSON）；有 refs → `POST /v1/images/edits`（multipart 重复 `image[]=@` 直传本地文件，顺序即挂载顺序）；响应取 `data[0].b64_json`
- **本地图直传、不需 imgbb**；参考图张数无硬限制，单张 ≤50MB；`n` 只能 1–4
- **size 直接用像素**（`1536x1024`/`1024x1024`），无需换算比例
- **跑批前必先探活**：普通任务确认 chatgpt2api 的 `/v1/models` 有 `gpt-image-2`；含彩铅任务时脚本另查 Flow2API `/models` 有 `models/gemini-3.1-flash-image`。后端没起就终止该路任务，不换模型
- 实测性能（2026-07-16）：文生图 ~30s/张，3 参考图 edits ~95s/张；6 并发全成、27–39s，相对单张无排队衰减
- 文生图（基础写实人物设定图/场景图）＝任务不给 refs；写实变体（换装/变老/伤妆）＝refs 挂基础写实版；彩铅参考图＝refs **只挂一张同状态写实版**并强制 Flow2API Banana 2，第一节同脸规则照旧；任务里的 `size` 对彩铅路由无效，脚本固定 9:16
- **主通道失败或无额度**：报告具体状态并停止该路任务；补充账号额度或更换渠道须按用户明确指令处理，不自动故障转移。
- 产物直接按命名规则写入本集 `资产图/`，生成完把资产清单对应行状态改"已生成·待用户审核"
- 实操脚本模式（04集验证）：任务清单 JSON（含全部提示词，UTF-8）+ 纯 ASCII PowerShell 脚本 + curl.exe；逐张重试 ≤3、追加日志；**中文内容一律走文件传递（--data-binary @req.json / -F "prompt=<file"），不走命令行参数**（防 Windows 控制台转码乱码）
- **编码血案（04集实证，硬规则）**：请求 JSON 落盘必须 **UTF-8 无 BOM**——PS 5.1 的 ConvertTo-Json **不转义中文**，按 ASCII 写盘中文全变问号，模型只收到数字（"55岁女性…"→生成了一张 55 岁生日贺卡）。【2026-07-31 用户裁定】批量跑图**一次性全量出，不做单张试跑、不等用户看图放行**；执行者只查接口、文件、格式和尺寸是否正常，仍不得看图代审画面——编码类翻车靠 Z2 落盘规则在提交前拦，画面问题由用户事后抽查走 /xiufu
- **图片审核归属（Z14）**：执行细节见 `.claude/skills/生产线总则.md`「图片审核归属」（全流程硬规则），此处不复述
- 用户只剩两件事：①提供产品实拍图 ②事后抽查（写实竖版双格设定图是否同脸同装同布局、场景是否可用，不合格点名重跑）——**`assets_ready` 由执行者技术核对通过后自置 true，不等用户验收**「原：③核对后把 assets_ready 改 true」
- 即梦网页手动生图**降级为备用通道**（API 故障、或需要人工反复挑图时）

## 一、人物资产：竖版双格人物设定图（2026-08-05 用户裁定终版：大头照＋全身照合在一张图，整图挂载；四格/三视图设定图仍全面退役）

> 裁定链：官方"双胞胎问题"章节证实多视图/宫格素材易被识别为多主体生成克隆人，四格制退役；官方推荐"大头照＋全身照两张分开引用"，用户裁定改为**合并一张竖版双格**（同日推翻两张分挂方案）——比四格少一半人物实例、比两张分挂省一半挂载位。双格仍属多视图族，故**反克隆约束句为强制配套**（T16）；若新链克隆率回升，按 CLAUDE.md 14.5 复验降级为官方两张分挂。存量集资产不回滚。

**每角色每状态固定输出两张图**（写实版＋彩铅版，同一竖版双格布局）：

1. 布局（9:16 竖版，两格上下排列、白色细分隔线）：**上格＝正脸头肩近照**（负责面部特征），**下格＝正面全身照**、从头到鞋完整入画，自然站立、双臂自然下垂（负责妆造/体型/服装）；
2. 两格必须是同一人物、同一年龄、同一发型、同一服装、同一体型，纯白背景、均匀影棚光、无文字无水印；
3. **写实人物设定图**负责身份母版、封面与写实关键帧；**彩铅参考图**专供视频生成与人脸修复挂载，成片仍按写实风格生成。

**命名**（沿用旧惯例，工具零改动）：
- 写实版：`R{n}-{角色名}-{状态}-人物设定图.png`
- 彩铅版：`R{n}-{角色名}-{状态}-彩铅参考图.png`
- 角色换服装/换年龄段/换状态 → 同状态另出这一对双版本，原图不动

**生成链（硬规则）**：
1. **基础写实版**：每角色第一状态可文生图直出固定竖版双格布局。
2. **写实变体版（换装/变老/伤妆）**：必须以基础写实版图生图，保持人物五官、脸型、发型骨相和体型一致，只改变指定状态；禁止独立文生图。
3. **彩铅版**：必须以同角色、同状态的写实人物设定图作为唯一参考图，经 `外部依赖/flow2api` 的 Banana 2（`gemini-3.1-flash-image`）图生图；固定 9:16、1K、极简提示词，不采用其他模型兜底。双格布局、人物身份、年龄、发型、服装、体型和表情基准不变，只转换绘画媒介；禁止从文字独立生成，禁止拿其他状态的图代替。
4. 存量集补拍/修复需要新参考图时，以该集原设定图（含历史四格图）作身份母图，图生图派生本节竖版双格图，再派生彩铅版；旧图保留作可恢复母图，不删除。

**写实人物设定图提示词模板**：
```
生成一张竖版2行1列人物设定图，两格上下排列、白色细分隔线：上格正脸头肩近照，下格正面全身照。
[人物描述块逐字放入]。两格为同一个人，五官、脸型、年龄、发型、服装、体型完全一致；全身格从头到鞋完整入画，自然站立，双臂自然下垂，表情平静。
纯白背景，均匀影棚光，无投影，无文字，无水印。[全局风格块]
```

**彩铅参考图提示词模板（必须图生图；2026-08-02 用户裁定：Flow2API Banana 2、9:16、逐字固定）**：
```
不改变图片，把图片风格转换成素描彩铅画
```

生成后交用户检查两版双格是不是同一个人、同一服装、同一布局；用户判定不一致并点名后再重跑——执行者不得自行看图代审。

**挂载用法（整图直接挂载，不裁切）**：
- 封面与写实关键帧：挂**写实人物设定图**。
- 视频生成：人物一律挂对应状态的**彩铅参考图**（一人一张一个挂载位）；素材声明 `将<图片N>中的[2-3个特征]人物定义为主体N（角色名）`，不写"图中两格是同一人"等解释句（T7）；提示词仍要求最终画面为手机实拍写实质感，不复刻彩铅纸纹。
- 人脸漂移修复：优先重做或替换彩铅参考图；只有用户指定或平台实测要求时才临时改挂写实版；需要更精准面部参考时，才从彩铅版上格临时裁一件补挂（裁切为修复备用手段）。
- **反克隆约束句（官方模板，人物挂载单元必加，双格挂载的强制配套）**：`视频全程禁止出现外形、着装、配饰完全一致的人物，不生成同款分身或双胞胎效果，每个角色在同一画面中只出现一个`——为 F25 白名单第三条负向句（官方点名例外，提示词规范 T16）。

## 二、人物描述块（写进本集资产清单.md，单一来源）

格式：**≤60 字**，含——年龄性别 / 脸型五官 / 发型发色 / 体型 / 服装（颜色+材质+款式，一集不换）/ **1–2 个硬特征锚点**。

> **未成年角色照剧本写真实年龄与身份词（2026-09-03 用户裁定解除去龄化默认，提示词规范 T10.1）**：描述块"年龄性别"位正常写年龄数字与孩子/学生等词，服装可写校服。去龄化只在通道拒绝后作修复手段：届时描述块改 **"男生／女生"** ＋外观锚点、校服改运动外套，分镜逐字复制保持一致（描述块是分镜的单一来源，改源头不改分镜）。

写作要诀：
- **面相跟角色定位**（2026-08-07 新增）："脸型五官"栏位按 `角色面相字典.md` 的定位菜单填写（男主/女主/大佬/反派男/反派女/好人配角），让观众第一眼读出角色身份；对标明示的反差设计保真沿用
- **具体压倒好听**："鹅蛋脸、细长丹凤眼、及肩黑色直发" 比 "清秀漂亮" 稳定十倍；禁 beautiful/漂亮/好看类空词
- **视觉档次跟经济身份（2026-08-05 用户裁定，偏好库·视觉档次）**：贫富差靠画面砸出来——富方角色的服装位写**高级具体词**（真丝衬衫、剪裁笔挺的深色西装、金丝眼镜、精致盘发、珍珠耳钉），发型妆面精致、整体帅气漂亮但仍用具体词表达；寒酸方写"旧但整洁"（褪色、起球、洗白，不写脏乱）。60 字预算内档次词优先级高于第二个硬锚点
- **主角光环（2026-08-05 用户裁定，P-88）**：主角尤其女主的描述块，穷困/劳动人设也要写清秀漂亮的具体词（眉眼清秀、肤色白净、气质利落），不因落魄降颜值档；**伤痕/手裂/病容等痛点特征禁入描述块与生图提示词**——痛点由台词与对手反应承载，不入画面（主角的疤类特征也不得当硬锚点，锚点改选服装/发型/饰品）
- **硬锚点是模型认人的抓手**：银手镯、右眉浅疤、藏青围裙、细银耳环——可视化、跨镜头稳定
- **≤60 字**：太长稀释权重反而漂

## 三、场景资产（底图＝360°环形全景图，挂载＝四宫格视角图）

> **每场景仍必产一张 360° 等距柱状环形全景图**（2026-07 三轮实测用户裁定）——它是场景的**权威底图与派生源**：天然首尾相连，各方向机位的空间连续性由这一张保证，改场景先改它再重派生。但**挂载资产＝由全景图派生的四宫格视角图**（2026-08-07 用户裁定全面替换，推翻 2026-07-26"全景整图直挂"——06集 A/B 实证柱形全景直挂在大远景下天花板出弧线接缝，四宫格版板缝笔直、地砖透视全直、保真度不降），派生命令与声明句见下方「四宫格派生资产」。**/zichan 默认先生成全景再派生四宫格**，不要用平面图充当底图资产。（05 集教训：曾误按已废的"v1 平面参考图"省事路线跳过全景，被用户点名——平面图**只**能作底图/降级，不作挂载资产。）含常驻人物的基准图变体在声明中点明人物与位置（如"床上有XX闭眼平躺、头朝床头"）。

- **生成渠道**（渠道政策见 §〇）：用 `工具/gen_grids_multi.py` 文生图**直接生成全景**（任务 JSON 不带 refs 自动走 `/v1/images/generations`），`size` 用 `1536x1024`，提示词套下方「全景提示词模板」（等距柱状 equirectangular 咒语，四个方向都要描述、光源方向唯一）。产物存 `S{n}-{场景}-全景.png`；**全景图不再直挂**，生成后按下方派生命令出四宫格再挂载。质量更高时用专训全景模型 Skybox AI（英文）或单图外扩工具（PanoPulse）补成 2:1。
- 全片场景主动收敛到 **1–2 个**（上限：纯剧情集 ≤4、带货剧放宽 ≤6）；**场景数 >2 时提醒用户收敛**。**本行＝场景数唯一权威源**（6-分镜契合 §5 与本 skill 入口均指此）；场景描述块（光影层逐字复用源）写进本集 资产清单.md，全景图存本集 资产图/。
- **场景档次跟剧情身份（2026-08-05 用户裁定，偏好库·视觉档次）**：富方/豪华场景的全景提示词必须写足华丽材质与空间感（大理石地面反光、水晶吊灯、整面落地窗、真皮沙发、层高开阔），光照按 Y20 明亮通透——豪宅拍出豪宅样，贫富差从场景图源头就拉开；寒酸场景写"旧但整洁、天光充足"，用材质表达旧（掉漆、磨损），不用灰暗表达。
- 全景为 1536×1024（3:2，非标准 2:1）时，接缝/极点（顶/底）轻微拉伸属投影正常，取景避开极端俯仰角即可。

**四宫格派生资产（2026-08-07 重启并同日扩为全量标准挂载）**：所有单元的场景挂载位一律挂四宫格视角图，全景图只作派生源不直挂。实测依据＝06集 A/B 单变量对照（柱形全景直挂大远景天花板现弧线接缝；四宫格版板缝笔直、地砖透视全直，保真度不降）；该 A/B 为旧通道实测，按 14.5 现通道 Symphony Seedance 2.0 **待复验**——首个新集顺带留意场景保真表现即可，若四宫格版出现场景漂移/翻车，该单元按 /xiufu 回退全景整图挂载并记录。
- **派生命令**（ffmpeg v360，从本集全景图直出，无需手动取景器；四个方向各出一张再拼格）：
```
ffmpeg -i S{n}-{场景}-全景.png -vf "v360=input=e:output=flat:yaw={0|90|180|-90}:pitch=0:h_fov=95:v_fov=70,scale=768:512" -frames:v 1 前|右|后|左.png
ffmpeg -i 前.png -i 右.png -i 后.png -i 左.png -filter_complex "[0][1]hstack[top];[2][3]hstack[bot];[top][bot]vstack" S{n}-{场景}-四宫格.png
```
- 素材声明写法：`图片N为该[场景名]的四宫格视角图，图中四格为同一房间的前、右、后、左四个方向的普通透视视角，作为场景基准，直接使用该环境`
- 产物存本集 资产图/，与全景图同占一个 S 编号（资产清单标注「四宫格·派生自 S{n}全景」，不占新挂载编号）；全景图仍是场景唯一权威底图，四宫格只是它的投影派生，改场景先改全景再重派生

- **降级/底图（仅备用，不作挂载资产）**：若只需快速平面底图（或作全景取景的底图存档），才用平面模板文生图，存 `S{n}-{场景}-参考.png` 并标「底图存档·不占挂载编号」。平面模板：
```

```

**进阶：720°全景虚拟影棚**（场景戏份重/跨集复用时启用——一次搭棚，机位随便取，结构光影绝对一致。场景标准、素材声明句、生成渠道均同上文本节开头，不再重述；专训全景模型 Skybox AI（skybox.blockadelabs.com，Realistic，英文提示词）质量最优，"单图扩全景"工具（PanoPulse 等）可从已定稿场景图外扩）

- 链式转身法已否决（2026-07 用户裁定），勿再提；"锚定图+图生图"思路仅用于人物变体

完整工作流五步：
1. **写全景提示词**（Skybox 用英文；通用模型模板见下）——四个方向都要描述到；**光源方向必须唯一且明确**（旋转取景后光影自洽的前提）
2. **生成 2:1 全景底图**：分辨率越高越好
3. **查缝＋修补**：左右边缘能否无缝相接；接缝/极点（头顶脚下）瑕疵用局部重绘修补
4. **虚拟取景**：把全景图拖进 `工具/全景取景器.html`（本地网页工具，用 Edge/Chrome 打开，禁 IE）——拖动环视、滚轮变焦、"📸截当前机位"；文件名自动带朝向/俯仰/视场参数，记进资产清单可精确复现同机位
5. **机位截图入库**：存为 `S{n}-{场景}-机位{m}.png`，分镜挂载引用；角色融合生图时提示词加前缀"参考图片环境生成，保持场景一致性，直接使用环境生成。50mm镜头，近景拍摄，无透视"

**全景提示词模板**：
```
无缝全球面360度全景图，等距柱状投影（equirectangular projection），左右边缘无缝衔接：
环视一周的[场景名]——正前方是[核心区域]，右侧是[…]，正后方是[…]，左侧是[…]；

```
注意：两极（头顶正上/脚下正下）有拉伸畸变属投影正常，取景时避开极端俯仰角即可。
