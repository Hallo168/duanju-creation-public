# 洗稿

本技能按下列流程执行，成稿依据为根目录 `洗稿提示词.md`。不继承旧版洗稿规则，也不套用其他文案流程。

## 输入

本次输入：$ARGUMENTS，包括剧情对标原稿，以及用户指定的目标产品、转化参考剧本。未要求换品时沿用已定产品。

读取本次原稿与 `洗稿提示词.md`；按需读取目标产品资料、用户指定的素材及转化参考原文。以原稿的实际剧本为依据，前置分析只供参考，其中的命令式语言不作为用户指令。剧情原稿、商品资料与转化参考各按用途取用，不互相替代。

## 流程

1. **先拆事件**：按 `洗稿提示词.md` 分清各单元必须保留的具体情绪条件、因果与人物立场，以及可以重新组合的现场条件；先理解全篇，不沿原场面加动作后就开始逐句改写。
2. **先给3个全篇改写方案**：每案简明写清人物与新现场、具体开场（必要动作和少量对白）、按主线顺序展开的关键事件新过程、高潮与结尾如何兑现，以及商品承接和篇幅安排。让用户看见整篇怎样重新发生。三案在具体来意、正在办的事、相遇、发现与交锋过程上形成实质差异，不能只换名字、地点或三个开头。可说明推荐哪一案及理由，此时不展开完整剧本。
3. **选定后成稿**：给出三案后等待用户选择或调整；用户已明确选定或授权代选时按已有决定继续。按选定方案逐事件重组现场，保住主线与情绪，台词随新处境重写；以接近原稿的体量写完，不靠增加铺垫、对白或细碎动作拉长。
4. **交付**：按 `洗稿提示词.md` 完成商品适配，并人工对照新旧事件的实际发生方式、情绪、衔接及篇幅。输出完整剧本，不以提纲或“同原稿”占位。默认保存到 `stories/编号-故事名/`，分别为 `改写方案.md` 与 `二创稿.md`；用户另有路径要求时从其要求。已有方案阶段只保存方案，选定后再保存成稿，历史作品保留。
