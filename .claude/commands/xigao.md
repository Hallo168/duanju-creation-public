你是洗稿线的编排者。本命令是独立线路，不走 /erchuang 的选题-成稿流程。

## 输入

对标原稿：$ARGUMENTS
- 编号或名字 → 在 `对标原稿/` 下定位唯一文件；定位不到或多义 → 列候选让用户挑
- 为空 → 列出 `对标原稿/` 全部文件让用户挑

### 开工前先判定集型（2026-08-01 用户裁定，硬关卡）

读完对标先判它是**带货稿**还是**流量稿**：

- **带货稿 → 洗稿成品必须带货**，不得洗成纯剧情稿。保带货段的出现时机与卖点递进节奏，话术全部重写。
- **流量稿 → 停放**（2026-09-11 用户停做流量素材）：不再自动往下走，停下报告"该对标是流量稿、当前不做流量集"并等用户指示。

### 产品规格取值（带货稿，2026-08-01 用户裁定）

产品规格的唯一权威来源是 `产品图/{产品名}/产品规格.md`，**不是对标原稿**。

1. 先在 `产品图/` 下找本片要卖的产品，读它的 `产品规格.md`。
2. **对标原稿写的规格（价格、赠量、包装形态、量词、克数、原价）与产品库不一致时，一律以产品库为准。**
3. 产品库里没有这个产品 → 照对标的规格新建 `产品图/{产品名}/产品规格.md` 再开工，并提醒用户补实拍图。
4. 派给执行者的产品条款直接引用产品规格.md 的内容，别让它从对标里抄价格。
5. **报价话术措辞仍要重写**——规格数字沿用产品库，但说法不得与对标原稿连续八字相同，多稿并行时各稿也要各说各的。

## 执行流程

**载体名单（2026-09-08 更新）**：提出换皮方案前，读取 `knowledge/现代载体与场景池.md`，并核对 `knowledge/选题黑名单.md` 的禁用项；将用户选定的职业、场所写入步骤2的换皮方案包。

1. **换皮选题提案（用户拍板，2026-08-03 裁定）**：编排者读完对标（带货稿再读产品规格）后，出 **3–5 套换皮方案**给用户挑选，每套一行打包：新剧名方向＋行业域＋势利角色新身份＋事故/危机类型＋信物类别＋证据载体类别＋**开场模式（画面钩/台词钩，从 `knowledge/爆款开头库.md` 取，不得与对标同模式——7号 §一 对标开场错开铁律，2026-08-08 用户裁定）**＋一句话新皮梗概；给推荐排序及理由。**用户选定后才派发生成**。一稿多洗（同一对标出 N 条）就让用户勾满 N 套——用户选出的方案天然互斥，取代旧规"编排者自行预分配互斥表层元素"；用户明确放权"你来定"时才由编排者代选，代选仍要保持各套互斥。流量稿按上述停做分支报告后不派发，不并入本轮。
2. **派干净子代理生成**：用 Agent 工具（sonnet-worker，model: "opus"）派发，brief 只给四样——`洗稿提示词.md` 路径、对标原稿路径、产品条款（取自 `产品图/{产品名}/产品规格.md`，不是对标）、**用户选定的换皮方案包**（作为硬约束：已定要素不得自行更换，方案未覆盖的细节仍按提示词自由发挥）；明令"除提示词外不得自行引入任何额外规则或项目知识"。**严禁让执行者看到同一原稿的任何历史洗稿成品**（会拿旧成品当底稿改，2026-07-30 调教实证）；重洗时把旧成品移出可见目录再派。成品写到 `洗稿成品/{原稿编号}-{新剧名}.md`（目录不存在则建）。
3. **独立复核查重**：不信任子代理自查，编排者自跑 `python 工具/洗稿查重.py <原稿> <成品1> [成品2 …]`（长期维护版，2026-08-03 自 运行垃圾 升格；内置行首格式脚手架剔除，一稿多洗时自动成品两两比对，不用再手写脚本或手工提正文），零命中才放行；有命中 → 把命中片段发回子代理重写该处，复检到零。
4. **编排者抽查三项高危**：①信物/证据载体是否真换了类别（执行者最易合理化蒙混项，同载体换叫法不算换）；②世界一致性（无跨时代跨世界语汇）；③**开场是否真换了模式**（对照 `knowledge/爆款开头库.md` 条目判——与对标同模式只换道具不算换，2026-08-08）。发现问题发回改，不自己动笔替写。
5. **到此为止，不投产入库（2026-08-01 用户裁定，覆盖 2026-07-31"洗完直接投产"旧规）**：查重零命中且两项高危抽查通过后，成品就留在 `洗稿成品/`，**不建 `stories/` 集、不写 `二创稿.md`**。要不要立集、何时立集由用户另行发话；用户发话后再按 CLAUDE.md 文件契约做转换。
6. **回报**：成品路径、新表层设定一句话（对照用户选定的换皮方案，标注执行偏差）、查重结论（两层口径见下）、三项高危抽查结论、篇幅百分比、集型（带货/流量）与产品规格取自哪份 `产品规格.md`。质量裁决权仍在用户。

## 查重的两层口径（2026-08-01 实证，编排者自跑，不采信子代理自查）

- **成品层**：洗稿成品 vs 对标原稿正文；一稿多洗时成品之间也要两两跑。比对前剔除"第N场／画面／人物动作／台词"这类格式脚手架（属"格式跟随原稿"，不算抄）。
- **正文层**（仅当用户另行发话立集、做了二创稿转换后才需要跑）：二创稿正文 vs 对标原稿、二创稿之间。**成品层全绿不代表正文层干净**——入库转换时新增的捧哏设问、产品演示段最容易撞，实测出现过 47 字连续重合。（2026-08-06 起带货段区间豁免——`工具/洗稿查重.py` 默认剔除【进入带货段落】–【返回剧情主线】，段外仍零容忍。）
- **台词层与画面层都要清零**：画面与动作文字下游要变成分镜提示词，同样会撞。
- 拿姊妹集的稿子当格式参照时，**只许看节结构与表格样式，不得沿用其任何台词、画面与动作文字**。
- 同骨架的**老集也要横向体检**，不只查本批。

## 边界

- 洗稿成品是独立台词稿，**洗稿线到 `洗稿成品/` 为止**（2026-08-01 用户裁定）：不建集、不写二创稿、不跑 /zichan 与 /fenjing。存量 45–50 集是旧规则下已入库的，原地保留不回滚。
- 用户审稿反馈照常蒸馏：直接改提示词本体 `洗稿提示词.md`（只加方向性规则，禁例句禁细枝末节），改前先查重避免与既有条款重复；调教史追加进 `工具/运行垃圾/tasks/洗稿调教/调教记录.md`。
- 产品规格类的反馈（价格、赠量、包装、克数）**不进提示词，改 `产品图/{产品名}/产品规格.md`**——那是产品事实的唯一权威来源。
