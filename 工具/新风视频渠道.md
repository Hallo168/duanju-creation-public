## 已验证的参考图提交方式

本次保存的是 **先上传参考图取得 `file_id`，再用这些 ID 提交视频** 的方式。适用于新风 `wan3.0-video-A` 的多参考图生成，或公网图片链接返回 `reference_preparation_failed` 的情况。

- 官方文档：https://xinfeng.best/video-api-docs/
- API 根地址：`https://xinfeng.best/v1`
- 上传与生成使用同一个有效的本站 API Key：`Authorization: Bearer <KEY>`。
- 实测参数：`wan3.0-video-A`、480P、30 秒、9:16、开启音频、关闭提示词扩写和水印。
- 2026-10-14 实时价格：480P 为 0.16 额度/秒，30 秒预计 4.8 额度；以后以实时能力目录为准。

### 1. 上传参考图

`POST /v1/files`，使用 multipart：

- `purpose=vision`
- `file`：实际图片文件；本次使用原 PNG 转出的 RGB JPEG 上传副本，原图保留。

逐图保存返回的 `id`，保持原分镜挂载顺序。上传回执与原图、上传副本的 SHA-256 一起保留，不把其他账号上传的文件 ID 混入当前请求。

### 2. 用文件 ID 提交视频

`POST /v1/videos`，设置 `Content-Type: application/json` 和预先保存的 `Idempotency-Key`。本次成功受理的请求结构：

```json
{
  "model": "wan3.0-video-A",
  "prompt": "原单元提示词，保持原文",
  "seconds": 30,
  "output": { "ratio": "480p-9:16" },
  "references": [
    { "type": "image", "role": "reference", "file_id": "第一张图的文件ID" },
    { "type": "image", "role": "reference", "file_id": "第二张图的文件ID" }
  ],
  "audio": true,
  "prompt_extend": false,
  "watermark": false
}
```

`references` 按实际张数填写，本次为 4 张；不得为套示例删图、换图或改台词。此处使用统一请求格式，不混入另一套 `input.media`、`parameters` 字段。

### 3. 查询与下载

- 查询：`GET /v1/videos/{task_id}`。
- 完成后下载：`GET /v1/videos/{task_id}/content`。
- 保存任务号、请求、回执及幂等键；已受理或结果未知时只查询原任务，不另建任务。明确返回 `submission_created=false` 才能认定该次未创建任务。
- HTTP 202 / `queued` 只表示受理。最终分辨率、结算分辨率以任务返回值为准，下载后核对文件、时长、尺寸、音轨和完整解码；这些不代表画面或对白验收。
